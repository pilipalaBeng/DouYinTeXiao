## 一、核心设计概览

**一句话定位**
把手机镜头当枪、把镜头里的真实环境当战场：Boss 是一只**锚定在真实物理空间**里的 3D 像素巨兽，玩家**转动手机**把 Boss 转进**屏幕正中固定的准星**、按住屏幕开火，把它打服认输的抖音 AR 像素射击互动特效。

**三句话复述原始期待**
- 是什么品类：抖音 AR 竖屏像素射击 · 单 Boss 速通（一局一 Boss）；
- 玩家做什么：举着手机**转动身体/手机**，把锚定在真实空间里的 Boss 转进屏幕正中的准星、按住屏幕持续开火，把血条打空；
- 爽点在哪：① 真实环境里"打 Boss"的临场感 ② 像素爆数字+震屏的即时打击反馈 ③ 顶着"朋友头像牌"的 Boss，天然想 @ 对方。

**目标用户**
抖音泛娱乐用户，主要 16–30 岁；偏好像素 / 街机 / 爽感射击；核心传播行为是"打完把结果甩给朋友 + 拉着对方来一局"。

**单局时长目标：20–40 秒，中位 30 秒（熟练 12–16 秒）**
判断与理由：
1. 抖音特效是"刷到即玩、无下载、无账号成本"的超低承诺场景，用户注意力窗口极短——前 3 秒决定留不留，一局必须在一次"手滑划走"之前给出完整快感闭环。
2. Boss 血条式的"磨血"体验如果拉长到 60 秒以上，完播与复玩率会显著下滑；反过来短于 10 秒又撑不起"打 Boss"的仪式感与社交梗。
3. 所以定"20–40 秒上限、熟练 10 余秒通关"：既保留 Boss 战的压迫—反打—终结节奏，又控制在竖屏短视频的容忍区间内。**超时未击杀即判失败**，制造紧迫感。

## 二、核心玩法循环

一个 30 秒内可闭环、可重复的循环。分四步，每步写清「玩家动作 → 系统反馈 → 状态变化」：

| 步 | 玩家动作 | 系统反馈 | 状态变化 |
|---|---|---|---|
| 1 瞄准 | **转动手机**（6DoF），把**锚定在真实物理空间**里的 Boss 转进**屏幕正中的固定准星**（准星不可拖拽） | Boss 进入准星容差圈（视口归一化 0.17）时准星高亮、Boss 微放大；提示音"嘀" | 准星进入容差 = 命中判定开启；转开则解除 |
| 2 开火 | **按住屏幕开火**（核心触发：按下开始、抬起停止） | 枪口像素闪光 + 后坐力（画面轻微上跳）+ 音效；命中则 Boss 闪白、抖动†、弹出伤害数字、溅出像素星 | Boss HP 下降；弹匣 -1；连击数 +1 |
| 3 承压/换弹 | 弹匣打空 → 点"换弹"；或用**人脸动作（张嘴/眨眼）= 重击触发**来打断 Boss | 换弹条读秒；Boss 进入反打动作（喷弹幕 / 冲撞 / 召唤）作为"惩罚窗口"；人脸重击则打断 Boss 当前动作 | 短暂无法输出；护盾/小怪出现；或反打被重击打断 |
| 4 终结 | 把 HP 打空 | 阶段 3 演出：Boss 举手认输、头顶出战牌"啪"落地 → 彩带像素爆炸 → WIN 结算卡 | 局结束 → 进入结算与分享；评级生成 |

> 触发方式严格控制在 **2 种**（平台边界）：**① 触摸按下/抬起 = 开火（核心）② 人脸事件（张嘴/眨眼）= 重击/打断**。**AR 相机朝向（转手机）属"操控输入"，不计入触发额度**；人脸挂点属"载体"，同样不额外叠加第三种触发。

**循环内核（30 秒闭环）**：瞄准 → 打 → 被反打 → 再瞄准 → 更狠地打 → 终结。玩家每分钟重复多次"瞄准—命中—爆数字"的小闭环，每 1/3 血量换一次机制，保持新鲜。

**乐趣来源排序（先定为什么好玩，再谈怎么做）**：
1. 打击即时感（hitstop 微顿帧 + 闪白 + 数字 + 震屏 + 音效，同帧触发）；
2. 真实环境里的临场感（Boss 叠在你自己拍的背景上，比纯贴纸多一层"在场"感）；
3. 社交梗（"我把带 XX 头像的 Boss 放倒了"）。

## 三、交互方案设计（AR 空间锚定 · 转手机瞄准）

平台实测边界（柯桥良核实 + 本机 AR 链路**已实测：组件可搭 + 判定式归一化；真机 SLAM 手感待验**）：**无好友/社交 API**；**触发限 2 种**；官方对象 **`AR Plane`（configId `PlaneAR`）** 一键搭出 AR 场景，**自动创建 `AR Camera` + `DeviceTracker` 组件**；**不做复杂 3D 骨骼 / 实时物理 / 服务器下发**。

> ⚠️ **实测范围口径（tech-architect 核定）**：v2 已实测的是 ① `AR Plane` 对象**可搭**、自动建 `AR Camera`+`DeviceTracker`（编辑器）；② 判定式用**归一化视口坐标**已验证（`vp.y≈0.522`，`implement-plan §10c`）；③ PC 预览行为（约 4s 收敛）。**未验的是核心玩法手感**——"转手机把 Boss 转进准星"依赖**真机 SLAM**（`node-plan §4` **#3 真机验证**、**#8 跟手性**，均**未做**；且 #8 明写"PC 预览无 SLAM，不作手感判据"）。⇒ **"链路跑通" ≠ "手感已过"**；手感是 v2 与 v1 的**唯一区别点、也是最大风险点，只能真机判**。

### 方案「AR 空间锚定 · 转手机瞄准」（唯一主案 · **链路已跑通，真机手感待验**）
- **世界结构（v2 核心）**：Boss 改用 **3D 版 `Image` 对象（configId `ImageEntity`）**，贴 DB16 像素贴图，**锚定在真实物理空间的 3D 世界坐标**上（不再贴在屏幕固定位置）。手机 AR 相机随玩家转动改变朝向 → Boss 在屏幕上**相对滑动**。
- **操作**：**准星固定屏幕正中**（不可拖拽）；玩家**转动手机**把 Boss 转进准星，**按住屏幕**开火（按下开始、抬起停止；连射由 250ms 闸门节流）。`TouchData.position` 在 v2 **仍存在但语义变更**——只用于「按下/抬起」判定开火，**不再用于瞄准定位**。
- **命中判定（v2 核心公式 · 判定式归一化已验；真机 SLAM 手感待验）**：
  ```
  worldPos = bossTransform.getWorldPosition()
  vp = arCamera.worldToViewportPoint(worldPos)   // 归一化视口坐标，原点左下，z=距相机距离
  if (vp.z <= 0) → 未命中（Boss 在相机背后）
  dx = |vp.x - 0.5|,  dy = |vp.y - 0.5|
  命中 ⟺ dx ≤ 0.17 且 dy ≤ 0.17
  ```
  实测佐证：`worldPos=(-81.865, 0, -197.076)` → `vp=(x, 0.522, ~122)`。`vp.y≈0.522` 证明返回的是**归一化值而非像素**；`vp.z≈122>0` 证明 Boss 在**相机前方**。
- **DeviceTracker 模式**：当前 `trackingMode = World`（6DoF 全 3D 世界跟踪，支持锚定空中目标）；另有 `Surface`（地面平面）/`Ceiling`（天花板）/`Orientation`（仅水平朝向 3DoF，更省性能）三种模式可选。
- **触发方式（2 种，符合上限）**：① 触摸按下/抬起 = 开火；② **人脸事件（张嘴/眨眼）= 重击/打断**（见核心循环第 3 步）。**AR 相机朝向属操控输入、不计入触发额度**；人脸挂点属"载体"。
- **对平台能力要求**：`AR Plane` + `AR Camera` + `DeviceTracker`（均为官方对象/组件，零自建 3D）。

### 明确否掉的旧口径（v1 → v2 变更说明）
- **否掉「屏幕空间 2D Boss + 手指拖准星（点哪打哪）」**：v2 改为 3D 世界锚定，准星固定屏幕正中、转手机瞄准；**不再有"2D 矩形吸附框"、不再有"准星跟随手指"、不再有"点哪打哪"**。
- **否掉「手搓陀螺仪 API 瞄准」**：v2 由官方 `DeviceTracker` 承担设备朝向，**不手搓 `GyroSensorAgent`（@alpha）**。
- **保留（不依赖）**：人脸事件仍作第二触发（可砍项）；Boss 动感仍只靠**序列帧（单动作 ≤24 帧）+ Tween**（无骨骼/物理）。

> 交互层与玩法层解耦：数值（第五节 HP/伤害/射速）与 Boss 阶段逻辑**与瞄准实现无关**；v1→v2 只替换"输入 → 命中判定"这一段（屏幕空间 2D 矩形 → AR 视口归一化容差），其余全部复用。

### 3.3 布局安全区与落位（官方 scene-game 规则 · 720×1280）
主操作区只能落在 **X[-340, +260]、Y[-400, +500]** 内，且**底部约 180px 为录制按钮禁区（y≥0.86 不安全）**，顶部信息栏、右侧工具栏需避让。
> **UI 实际落位更严口径（以 art-spec 为准）**：可交互 UI 元素的落位带 = **X ∈ [-340, +260]、Y ∈ [-220, +430]**（底部禁区 Y ≤ -220、顶部信息栏 Y ≥ +430）。**UI 安全区布局归美术定，下列具体坐标均服从 art-spec**；本节只声明"落在这个带里、不越界"。

据此排布：
- **血条**：顶部信息栏下方，**占位 Y 约 +348 ~ +428**（对齐 art-spec §3.4：`hp_frame` 中心 (X=-40, Y=+380)、护盾条 Y[+404,+428]），**不压顶部信息栏（Y<+430）**；
- **准星**：**固定在屏幕正中 (X=0, Y=0)**（v2：准星不可拖拽、不随手指移动）；命中判定即以屏幕正中为基准（视口 0.5/0.5，容差 0.17）。⚠️ art-spec §3.3 旧写"安全区几何中心 (X=-40, Y=+60)"，**v2 以屏幕正中为准**，需美术侧同步（见第十三节 风险）；
- **Boss**：3D 世界锚定，投影位置随转手机滑动，可出现在安全区任意位置（不受 UI 落位带约束）；
- **开火区**：**全屏按住即开火**（按下/抬起不承担瞄准）；开火热区需避开底部 180px 录制禁区与顶部信息栏，按下点落在禁区时按"最接近的安全点"宽容处理；
- **换弹 / 重击提示按钮**：安全区内右下角，**按钮中心 Y ≥ -220**（对齐 art-spec §3.5"所有可点按钮中心 Y ≥ -220"），**不进入底部录制禁区**；
- **结算卡**：居中弹出（art-spec §3.6：`card_bg` 中心 (X=-40, Y=+100)，占位 Y[-220,+420]），全部元素落在 X[-340,+260]、Y[-400,+500] 内。

### 3.4 音效（官方规则：游戏类效果必须含核心操作音效 + 反馈音效）
必配三类：**射击音**（每次开火）、**命中音**（含连击叠音）、**胜负音**（WIN / 失败各一条）；另加 Boss 落地、阶段切换、准星锁定音。

## 四、Boss 设计

### 4.1 像素形象方向
- **原创怪兽，不指向真人**：Boss 本体是原创像素巨兽（暂名 **Boss-01「圆滚魔像」**）——圆钝身体、独眼大眼、粗短小腿、头顶一对小角，憨中带凶。逻辑画布沿用大元素 96×96 或 128×128（只许整数倍），DB16 16 色内完成配色，Nearest Neighbor 采样。
- **承载与运动方式（v2）**：Boss 本体是 **3D 版 `Image` 对象（configId `ImageEntity`）**，**锚定在真实物理空间的 3D 世界坐标**，贴 DB16 像素贴图。其动感仍只来自 **序列帧动画（单动作 ≤24 帧）+ Tween（位移/缩放/旋转）**，**不做 3D 骨骼、不做实时物理**；命中判定用 **AR 视口容差（0.17）**，不做弹道物理。
- **头顶"出战牌"挂点**：Boss 头顶留出 16×16 或 24×24 的像素相框挂点，用来放**双轨头像**（轨 A 预设 6 选 1 / 轨 B 摄像头取像，见 §六）。头像被**像素化为 16×16/24×24 静帧 + 加一圈像素相框**，视觉上就是一个"举在头上的小牌子 / 应援旗"，**明确是"牌子"而非把真人脸贴成 Boss 本体**（见第六节合规处理）。
- 情绪靠**眼睛与头顶牌**表达：受击→眯眼龇牙；暴怒→眼睛变红加粗；认输→眼睛弯成 ^ ^、牌子垂下。全部在 DB16 内完成，不新增颜色。

### 4.2 血量与阶段（≥3 个机制变化）

| 阶段 | 触发线 | 名称 | 机制变化 | 玩家应对 |
|---|---|---|---|---|
| 阶段 1 | HP 100%→66% | 常态试探 | Boss 缓慢左右摆动，无主动攻击，作为教学/暖场；露出"常规受击"反馈 | 熟悉瞄准与开火 |
| 阶段 2 | HP 66%→33% | 暴怒 | 眼睛变红、体型微胀、摆动速度加快；周期性**喷像素弹幕**（无需躲避硬判定，命中只扣连击/短暂致盲）+ **召唤 2 只像素小怪**挡在身前（可打可不打，不打则挡住部分判定） | 保持连射、抽空清小怪或直接抗 |
| 阶段 3 | HP 33%→0% | 护盾 + 假死 | ① **开护盾**：Boss 举起像素护盾，**护盾期 HP 冻结、不下降**；护盾有独立**蓝盾条**（＝破盾进度）。命中**身体**：盾量 −6%/发（可硬磨但慢）；命中盾上闪烁的**"核心点"**（每 1.2s 随机闪一次）：盾量 −34%/发 —— **约 3 次核心命中破盾**。盾量归零 → **破盾 → 2s 全额伤害窗口（此时 HP 高速下降）**；窗口结束**回盾，上限 2 轮**，第 2 轮窗口后盾永久消失。② **假死**：HP 降至**约 15%（区间 10%–20% = 约 360 血）**时 Boss 突然瘫倒装死、血条"假空"0.8s——若玩家停火就会被反打回血 5%，继续猛打则识破（给一句调侃提示"它装的！"） | 抓核心点破盾（约 3 次）；假死时不要停火 |

> **状态切换帧（供特效/动画挂点，与 vfx-spec 对齐）**：阶段 2 = HP 跨 **66%**；破盾 = **核心点被打破**；假死 = HP 达 **约 15%（10%–20%）**；认输 = **HP=0**。阶段切换时「**震屏 + Boss 变色 + 像素台词**」三件套**同帧触发**，满足"1s 内可感知"。

阶段切换用**屏幕轻微震屏 + Boss 变色 + 一句像素台词**做提示，确保玩家一秒钟内感知"换阶段了"。

### 4.3 受击反馈（四件套，同帧触发）
1. **微顿帧（hitstop）**：命中瞬间全局停顿 40–70ms，强化打击感；
2. **Boss 闪白 + 抖动†**：本体 1–2 帧纯白覆盖 + 位移抖动†（**位移实现 = `ContentRoot` 整屏震屏；Boss 本体是否随动待真机 A/B**，见文首口径注）；
3. **伤害数字**：像素数字从命中点弹起并上飘，暴击数字更大更黄（DB16 的 `#dad45e`）；
4. **像素星粒子 + 音效**：命中溅 3–5 个像素星，配"啪/咚"音效；粒子总数受规格约束（全场 ≤50）。

> **颜色纪律（合规强化，与 vfx-spec 对齐）**：命中反馈（像素星、伤害数字）**只允许白/黄**，**禁用 DB16 红 `#d04648`**——红色粒子会被审读成"血"。**红色仅保留给 UI 血条与 Boss 暴怒眼睛**。设计案不依赖任何"红色命中粒子"。

### 4.4 击杀演出（去暴力化）
HP 归零 → ① Boss 举手投降、眼睛弯成 ^ ^、**无血无伤口** ② 头顶出战牌"啪"落地并被玩家准星"夹"住 ③ **像素彩带(20) + 星星(8) 同帧 burst = 28 粒子**（≤30，留 2 余量）④ 蹦出 WIN 与结算卡。**全程无血、无惨叫、无身体破坏**，语义为"认输/被放倒"，不是"杀死"。

## 五、数值设计（具体数字表格）

所有数值给**区间**并标注调参依据；单点值为首版落地建议。

## 六、社交互动设计（头像来源**双轨** · 轨A 预设 / 轨B 摄像头取像 + 合规处理）

### 6.1 钉子 A —— 合规处理（先解决语义与呈现，再谈接入）

原始设想"好友头像装在 Boss 头上、被枪打死"直接触及 **① 非自愿换脸/深度伪造（冒用他人肖像）** 与 **④ 血腥暴力/恐吓**两条红线。处理方案如下：

1. **语义替换**：全项目禁用"杀死/击杀/爆头/献血"等词。统一用 **「放倒 / 击退 / 挑战成功 / Boss 认输」**。Boss 归零的表现是"举手投降 + 瘫倒打转"，不是死亡。
2. **呈现去暴力**：无血液、无伤口、无骨折、无惨叫、无身体破坏；受击只有闪白 + 抖动† + 像素星；终结是彩带 + 星星 + 认输表情。击杀演出见 4.4。
3. **头像定性为"牌子"不是"人脸本体"**：头像被处理成 **16×16/24×24 静帧像素小相框**，挂在 Boss 头顶当"出战牌 / 应援旗"。视觉与文案都强调"这是顶在**出战对象**头上的牌子"，**不是把 TA 变成了怪物**。关系语义从"打某人"改成"打赢举着其人应援旗的怪物"。
4. **不做换脸、不做模仿**：头像**仅为静帧贴片**，不做表情驱动、不做口型、不生成对方言行、不合成熟人脸合成——从根上避开深度伪造。
5. **来源限定（双轨，均不引入"相册照片"）**：① **轨 A（默认 / 本轮）** = 内置**预设像素头像 6 选 1**，**零真人照片、零外部素材**；② **轨 B（增强 / 待验）** = 用户用准星对准**当前在场者**、以**摄像头实时取像**定格为战牌（**API 层已验证存在，真机未验**），**不存储、不上传、不导出，仅存活于本局运行时纹理**。两条轨道**都不读取相册、都不接受外部照片导入**（原"相册选图 + `Image Picker (Head)`"路径**已废止**，见 6.2）。
6. **不做识别、不留存**：轨 B 取像仅把画面中央一块方形区域当**运行时贴片**，**不做人脸比对、不做身份识别、不写盘、不上传**；本局结束即随纹理释放。

> **合规自检结论（钉子 A · 据实重估）**：经上述处理后，本特效用"**举着原创像素怪头顶应援牌**"替代了"把真人脸贴到 Boss 上"，并用**双轨**取代已废止的"相册选图"。结论**挂条件、不再作无条件断言**：
> - 轨 A：**无真人内容** → 该类红线**不适用**；
> - 轨 B：**已缓解**（条件：取像只存活于本局运行时纹理，**不落地存储、不上传、不导出**，用户须**主动对准当前在场者**拍摄）；
> - 暴力侧：由"语义替换（放倒/认输）+ 无血 + 认输演出"守住。**结论：双轨方案可发布；轨 B 仅在其前置条件全部满足后才允许上线。**

### 6.2 钉子 B —— 头像来源**双轨**设计（技术已核实）

> **演进史（两次降级，均已废止）——明写原因，不再复用**：
> - **已废止 ①「读取好友列表」**：平台**无任何好友/社交 API**（全库零命中，可复核）→ **作废**。
> - **已废止 ②「相册选图 + `Image Picker (Head)` 自动抠头」**：本版编辑器**不支持该对象**（实测报 `Unknown scene object config id`），APJS **无对应 picker API** → **作废**。**此前建立在"用户从相册主动选图"上的合规理由随之失效**（见 §十一 已重写）。
> - **现行主案 = 双轨**：**轨 A**（默认兜底，本轮必做）+ **轨 B**（增强候选，待拍板）。

**轨 A：预设 6 选 1 像素头像（★ 默认主案 · 本轮必做）**
- 素材：**内置 6 款原创像素头像**（12 张资产已产出：`avatar_XX_64` 选择页用 / `avatar_XX_16` 上牌用）。
- 流程：**进局前选择页 6 选 1**（默认高亮第 1 款，**3s 无操作自动用默认值进局**，**不阻断玩法**）。
  - **防误覆盖规则**：倒计时在用户**首次交互后取消** —— 否则会出现"用户在 2.8s 点选、3.0s 被默认值覆盖"的错误分支。

> **超时值单一来源 = 本节：3s。** 其它文档一律引用本节，不得另立值（`README` / `implement-plan` / `submit-checklist` 引用处同）。

- 上牌：选中款 → 取 `avatar_XX_16` → 加像素相框 → 挂 Boss 头顶出战牌。
- 合规：**零真人照片、零外部素材、零上传** —— 不引入任何肖像数据。

**轨 B：摄像头取像头像（增强候选 · 待拍板 · 本轮不排工期）**
- 机制（**API 层已验证存在，真机未验**）：官方 APJS `APJS.CaptureFrameHelper.captureCameraOutput(camera, cropRect, resolutionRatio): Texture | null`（`APJS.d.ts` L1620）+ `APJS.Image.texture` setter（L4733）—— 用户**把准星对准要出战的那张脸** → 快门 → 抓画面中央一块方形 → **定格成 Boss 头顶战牌**。
- 与瞄准同源：**这与 v2"转手机瞄准"是同一个动作**——瞄准第一次不只是判定命中，还是"**选修出战对象**"；梗从"打认识的人"升级为"**打现在就站在你面前的人**"。
- 流程（**规划**）：开场引导"**把准星对准要出战的那张脸**" → 快门（可跳过）→ 取像定格 → 像素化 16×16 + 相框 → 上牌；**跳过 / 取像失败 → 回落轨 A 预设头像，不阻断**。
- **落地前置条件（缺一不可，未满足不上线）**：① 真机验证 `captureCameraOutput` 可用性与帧延迟；② 确认 `Texture` 能挂到 `ImageEntity` 并可刷新；③ 确认**不写盘、不上传、不导出**。
- **状态标注：规划 / 待验证。验证通过前，轨 A 始终是默认入口，轨 B 只作可选项。**

> 两轨共享"出战牌挂点 + 像素相框 + 默认兜底（不阻断）"的公共逻辑。**玩法与数值全程不变**，只有"出战牌素材来源"这一段替换。

## 八、失败 / 超时处理 与 重复可玩性

**失败与超时**
- 时限 40s 内未打空 HP → 判失败：Boss 大笑跳走，弹结算卡"它跑掉了"，**一键再来一局**（不需要重进特效）；
- 失败不加惩罚、不锁功能，保证"秒重开"；
- 中途切后台/断相机：**自动暂停**，回到前台恢复，不判失败（避免误杀体验）。

**随机性来源**
1. Boss 阶段行为随机（暴怒摆动方向、弹幕角度、小怪数量 2–3 只）；
2. 护盾核心点的闪烁位置随机；
3. 像素 Boss 皮肤随机（MVP 1 款，迭代 +2 款：火山款 / 机器款）；
4. 出战牌相框随机（4–6 款像素相框）。

**多 Boss / 复玩驱动**
- MVP **只做 1 只 Boss**（范围控制优先）；迭代再扩到 3 只，并按"通关评级"解锁。
- 复玩驱动：① 追求 **S 评级**（看第八/九节的评级表）；② **最短耗时挑战**（结算显示个人最佳）；③ **换出战对象再战**（社交驱动复玩）；④ 分享卡被好友点赞/接战 → 回流再玩。

## 九、结算与分享设计（平台内可实现形态）

**结算卡（静态，平台内可生成）**
- 版式：像素风竖版卡，含 ① Boss 立绘 ② 头顶出战牌（头像/名字）③ 结果字"WIN!/再来一局" ④ 三项数据：耗时、命中率、最高连击 ⑤ **评级 S/A/B/C** ⑥ 一句调侃文案（如"这只 XXX 被放倒了，就这？"）。
- 评级规则（示例）：S = 时限内剩余时间 ≥50% 且命中率 ≥70%；A = 命中率 ≥60%；B = 通关；C = 未通关。

**分享形态（均限平台内）**
1. **保存结算卡到相册 / 一键分享**（抖音内分享通道）——**主推**；
2. **@ 好友**：头像来源为**轨 A 预设 / 轨 B 摄像头取像**（轨 B 待验），**特效内不做账号级 @**（无社交 API）；社交指向靠用户**手动在抖音发布时 @ 对方**完成，特效只提供"带头像的结算卡"作素材；
3. **挑战码（可选，待确认）**：若平台支持**文字输入**，结算卡可印一串像素字母数字码，好友在特效内输入还原同款 Boss + 出战名组合；**不支持则整条砍掉**。

**明确不做的分享形态**：不做外链、不做服务器排名榜、不做需要后台下发的对局（触碰"不做服务器下发"红线）、不做账号级好友拉取。

## 十三、风险与可砍项

**风险**
1. **手搓陀螺仪瞄准（@alpha 未验证）** → **v2 已弃用**，改由官方 `DeviceTracker`（随 `AR Plane` 自动创建）承担设备朝向与锚定；无 @alpha 依赖。**新增风险**：PC 预览无 SLAM，AR 相机需约 4s 收敛（见 README/submit-checklist 的 PC 预览验收口径）。
2. **头像社交钩子两次降级** → 好友列表（无社交 API）、相册选图 `Image Picker (Head)`（编辑器不支持该对象）**均已废止**；现行主案＝**轨 A 预设 6 选 1**，**轨 B 摄像头取像**为待验增强。
3. **取像失败 / 用户跳过** → 已用"**回落轨 A 预设头像、不阻断进局**"化解。
4. **肖像合规** → 轨 A 无真人内容；轨 B 以"**用户主动对准当前在场者 + 不存储 / 不上传 / 不导出 + 不做识别 / 模仿**"缓解，**挂条件放行**。
5. **像素规格包体超限**（序列帧多）→ 调色板复用 + 帧压缩，控制在 ≤2MB。
6. **轨 B API 真机未验** → `captureCameraOutput` 仅证明 API 存在；**真机帧延迟、`Texture`→`ImageEntity` 挂载均未验**。**验证不过则轨 B 整体砍掉**，回落轨 A，不影响发布。

**可砍项（范围控制，按优先级从低到高砍）**
- 过热机制（连射惩罚）→ 先砍，保留换弹即可；
- 召唤小怪 → 砍，暴怒只保留弹幕；
- 多款 Boss 皮肤 / 多款相框 → MVP 各留 1 款，迭代再加；
- 挑战码（需文字输入）→ 平台不支持则整条砍，只保留"保存结算卡"；
- 人脸事件重击（第二触发方式）→ 先砍，只留触摸点击，保证触发数 = 1 更稳妥过审。

**MVP 最小可发布集**：1 Boss · 1 皮肤 · 3 阶段（常态/暴怒/护盾）· **AR 空间锚定（Boss 3D 锚定物理空间 + 屏幕正中准星 + 转手机瞄准 + 按住开火）** · **头像＝轨 A 预设 6 选 1（无真人内容、默认即选、不阻断）** · 结算卡保存分享 · 射击/命中/胜负三类音效 · 全部 UI 落布局安全区。其余（含轨 B 摄像头取像）全部列为迭代。

### 已由技术核实的结论（v1.1 对齐项）
1. **头像来源（决策记录）**：**B1** 读取好友列表 → **已废止**（平台无任何社交 API）；**B2** 相册选图 + `Image Picker (Head)` → **已废止**（本版编辑器不支持该对象，实测报 `Unknown scene object config id`，APJS 无 picker API）；**B3** 摄像头取像 → **新候选**（APJS `CaptureFrameHelper.captureCameraOutput` + `Image.texture` setter，**API 已验存在 / 真机未验**）。**现行主案 = 轨 A 预设 6 选 1**；轨 B（=B3）待拍板。
2. **瞄准**：v2 = **AR 空间锚定 + 屏幕正中固定准星 + 转手机瞄准**（官方 `AR Plane`/`AR Camera`/`DeviceTracker`；**已实测"组件可搭"，真机 SLAM 手感待验**）；不手搓陀螺仪；无"触屏拖准星/头部转向"备选。
3. **触发**：固定 2 种 = ① 触摸点击=开火 ② 人脸事件=重击。
4. **表现**：Boss 为 3D 世界锚定 `ImageEntity`；动感 = 序列帧(单动作 ≤24) + Tween；命中 = AR 视口容差 0.17；无骨骼/物理/联网。
5. **布局**：UI 落 720×1280 安全区 X[-340,+260]，**UI 落位带 Y[-220,+430]**（对齐 art-spec）；血条 Y≤+428、按钮中心 Y ≥ -220，避开底部录制禁区与顶部信息栏。
6. **音效**：必配射击音 + 命中音 + 胜负音。

本设计案据此定稿，可交付美术/动画/特效/音效/程序执行。

## 十四、细节修改批次（2026-10-14 · 已落地并运行期验证）

> 本批 4 项由用户在"整体流程跑通"后提出。**结论已由像塑预览实测验证**，非规划推断。

### 14.1 玩家武器：AK 造型像素枪（新增）
- 定位：**屏幕层常驻 HUD**，从屏幕下方伸入、斜指屏幕中心，营造"第一人称持枪"观感。
- 美术：**像素粗模**，AK-47 为原型（木托 + 金属枪管 + 弯弹匣 + 准星座），一眼可辨为枪即可，不追求精细。
- 规格：逻辑 **128×64** → 导出 ×4 = **512×256** PNG 透明；色板 DB16（实测 6 色）；Nearest 采样。
- 对象：`枪` 挂 `玩法根` 下，`renderOrder = 10`（**全场景最低层**，压在准星/血条之下，不遮 UI）。
- 与准星关系：枪在下、准星在上——准星需始终可辨（**art-spec §3.3 裁定**）。

### 14.2 Boss 换型：地面独眼石魔 → 空中飞行怪
- **造型**：蝙蝠状飞行怪（张开双翼 + 红色圆眼 + 头顶双角），替代原「独眼石魔」。逻辑 128 画布 → 512×512 导出，DB16（实测 7 色）。
- **飞行**：Boss 在真实空间内**上下浮沉 + 横向漂移**，合成柔和 8 字悬停轨迹。
  - 实现：脚本 `onUpdate` 在基准世界坐标叠加 `sin` 位移（`flyAmp=1.2 / flySpeed=1.2 / flySway=0.6 / flySwaySpeed=0.7`）。
  - **实测依据（2026-10-14）**：写入 `setWorldPosition` 后立刻回读，y 值恒等（误差 0），且预览中对象确实位移出屏 → **3D 世界锚定对象的 Transform 可被脚本驱动，AR 追踪不覆写**。
  - 玩家可**实时转动手机**把飞行中的怪转进屏幕正中准星，符合原设计"转手机瞄准"的操作层。
- **尺寸**：`localScale 8 → 4.8`（约 6 成）。原因：新贴图双翼张幅大，原尺寸下几乎占满屏宽、会压住准星与血条。

### 14.3 【砍项】吐火球 + 下蹲躲避（引擎不可实现）
- 用户原意：Boss 不定期吐火球，玩家下蹲改变高度躲避，以"较大高度变化"判定躲避成功。
- **实测结论（2026-10-14，运行期探测 11 项全负）**：APJS 用户脚本层**不存在任何设备姿态/高度传感器**——
  `APJS.GyroSensorAgent` / `RotationSensorAgent` / `AccelerometerAgent` / `Gyroscope` / `SensorAgent` / `buildGyroSensorAgent` 全部 `undefined`；`DeviceTracker` 组件实际仅剩 `_rtti/_typedRtti` 内部字段；`AlgorithmManager.getSlamInfo` 亦为 `undefined`（无 SLAM 位姿入口）。
- 按用户指令「**如果不行的话吐火球这个逻辑也都不用加了**」→ **吐火球 + 下蹲躲避机制整条砍掉**。

### 14.4 准星结算后隐藏
- 规则：**结算（胜利或失败）后准星隐藏**，防止占用 UI 污染画面；**重开（resetGame）时恢复显示**。
- 实现：`setCrosshairVisible(on)` —— `win()` / `lose()` 传 `false`，`resetGame()` 传 `true`，形成闭环。
- **运行期验证**：结算帧准星消失、结算文案居中显示；重开后准星重现。
