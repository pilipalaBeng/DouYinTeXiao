## 0. 前置结论（TL;DR）

1. **50 粒子够用，但余量已收窄（250ms 闸门联动重算后）**：全特效「现实峰值」最大 **36**（击杀瞬间），余量 14；「理论全叠加（防御性上界）」重算后 **= 50，恰等于红线本身、余量为 0** → 因此**必须挂运行时粒子预算管理器**（软顶 46 / 红线 50）才能保证任意时刻 ≤50 —— 该管理器即柯桥良 §3.1 的自动降级，本文补上**降级优先级顺序**（谁先被削）。
2. **不启用 `ParticleEmitter2D`**。官方路由明确它只服务 **2D 流体/液体（水流、水池、黏液）**，不适用火花/碎片/星星。像素粒子一律走 **内置 `Basic Particles` + 换 `MainTexture` 为 DB16 像素贴图**（零自定义 shader、零额外包体）。
3. **内置模板能让它「服从 DB16 与像素风」—— 靠换贴图，不靠改模板**。模板自带的彩色软边贴图必须整体替换为「DB16 量化的硬边像素 PNG」；颜色锁死贴图色值，形态锁死硬边。**可行**（详见第四节）。
4. **像素星绝不用红色**（DB16 的 `#d04648` 是 UI 色，粒子用红会读成「血」）。命中星只用 `#deeed6` / `#dad45e`。
5. **闪白用「硬切」不用 Tween 插值**：albedo 直接置 `#deeed6` 冻 2 帧再复位，避免插值出 DB16 外的中间色。
6. **顿帧冻结 Boss 动画与输入，但不得冻结 L4 特效层**（否则闪白和粒子被冻住）。经柯桥良核 APJS 源码确认：本引擎**无全局 timeScale / unscaledDeltaTime**，只能走「冻结 Boss 动画 `AnimatedTextureProvider.pause()` + Touch 回调 `hitstopTimer` 守卫 return」，L4 因未动全局时间而照常跑（见 6.1）。
7. **[已与 tech-architect 定稿的实现细节]** ① 换贴图严格按官方顺序 `stop() → setTexture("MainTexture") → play()`，贴图源用**隐藏 Screen Image TexHolder**；② 屏幕震动动**专用 `ContentRoot`**（2D Scene Object 挂 2D Camera 下，偏移 `ScreenTransform.anchoredPosition`），**不占 6 层额度**，禁动真 Camera；③ 粒子降级里的 `setFloat(rate,…)` 键**未证实**，落工程第一步必须 `hasFloatKey` 实探，无该键则改用 `setEnabledInHierarchy(false)` / 调 `Lifetime`；④ 降级日志前缀 `[guard]`。

## 一、特效语言与配色

### 1.1 视觉语法（三条铁律）

| 语义 | 视觉语言 |
|---|---|
| **命中（普通）** | 短促、就地、白 → 白黄；闪白 1 帧 + 3 白星 + 白色数字上飘 + 轻震 |
| **命中（暴击/破盾核心）** | 更亮更大、加黄 `#dad45e`；5 星 + 大号黄数字 + 中震 + 命中标记变大 |
| **危险/阶段推进（暴怒）** | 红眼 + 全屏一圈青白脉冲 + 大震 + 像素台词 |
| **守护/解题（护盾）** | 核心点每 1.2s 闪一次青 `#6dc2ca`，破盾=青白碎片外散 |
| **胜利（认输）** | 暖色上行、彩带 + 星、无向下/无爆裂；黄白为主 |

**用色纪律**
- 命中类粒子/数字 → 只允许 `#deeed6`、`#dad45e`（白/黄），**禁用 `#d04648`**。
- 血条 UI 渐变（非粒子）：`#6daa2c` → `#dad45e` → `#d04648`（满→中→危）。这是 UI 色，语义是「血条」不是「血」。
- 暴怒眼/危险提示可用 `#d04648`（角色特征，非伤害表现）。
- 彩带：`#dad45e` `#d27d2c` `#6dc2ca` `#d2aa99` 四色轮转（暖色主、冷色点缀）。

### 1.3 发光与混合方式

- **默认 alpha 混合**（保证画面色 = 贴图色，最守 DB16）。
- 仅「光核」小面积允许 additive，且色必须是 DB16 精确值（`#deeed6` / `#dad45e`）。
- 说明：additive 叠在摄像头画面上产生的合成色属「合成结果」，不计为「使用色板外颜色」；但为提审稳妥，**主打 alpha，additive 只用于 ≤8px 光点**。

- 文件（遵守宪法：英文小写 + 下划线）：`<类别>_<名称>_<变体>.png`

### 3.4 运行时粒子预算管理器（保证 ≤50 的硬机制）

**接入点**：L4 命中特效控制器（同一脚本内集中管理 E2/E2′/E3/E4/E5/E6）。
**由谁实现**：tech-architect 实现脚本骨架（柯桥良 §3.1 已定 API），vfx-director 提供**阈值、降级优先级、每档数值**。
**⚠️ 落的第一个动作是实探 key**：`setFloat` 只能作用于 VFX Graph **暴露的参数**。落工程第一步 `query_knowledge` 查该 Basic Particles 资产暴露的 key，或脚本枚举 `asset.hasFloatKey(name)` 打日志。**未探到 rate 键前不得写死 `setFloat("rate", …)`**。

```
// 每帧 onUpdate（O(1)，无 new、无遍历分配）
enableAliveParticleCount = true;                 // 初始化一次
alertLevel = Σ emitters[i].aliveParticleCounts   // 求和

if (alertLevel > 50) {                           // 红线硬保护（唯一真正的 ≤50 保证）
  for each emitter: stop(APJS.VFXStopBehavior.StopEmitting);   // 停发 = 硬保证
  applyPeakTrim();                               // 削峰：见下方「降级杠杆」
  log("[guard] budgetDropped, alive=" + alertLevel);
} else if (alertLevel > 46) {                    // 软顶：按优先级降一档
  applyDegradeLadder(alertLevel);
} else if (alertLevel < 40) {                    // 回滞恢复
  clearDegradeLadder();                          // 低于 40 再恢复，避免抖动
}
```

**降级杠杆（按可用性择优，key 实探后定）**
1. **首选（已知可用）**：`setEnabledInHierarchy(false)` 关闭对应 emitter 对象 —— 立即压 alive，零 key 依赖。
2. **次选（key 实探通过后）**：`setFloat("<真实键>", <真实键>*0.5)` 降发射率；**键名以实探为准，不用假设的 `rate`**。
3. **兜底**：调 `Lifetime` 缩短粒子存活，加速自然回收。
> 三者都能压 alive；**「stop 停发」是硬保证，阶梯只是削峰**——这个分工不变。

**降级阶梯（回滞 40↔46，避免边界抖动）** —— 从「最该砍」到「最后才砍」：

| 顺序 | 对象 | 动作 | 释放额度 |
|---|---|---|---|
| 1 | L1 环境氛围粒子 | 直接停（本项目 L1 本就留空） | — |
| 2 | E6 认输星星 | 关（视觉冗余，彩带已够） | 8 |
| 3 | E2 命中星 | 单次 3 → **2** | 2–4 |
| 4 | E4 暴怒脉冲 | 6 → **3** | 3 |
| 5 | E5 彩带 | 20 → **12** | 8 |
| — | **不砍** | E3 破盾（机制反馈）、E2′ 暴击星、闪白/数字/震动（本就 0 粒子） | — |

**结论**：按上表，S7（50）在 alive>46 时先砍 E6（-8）→42，已回线下。**但 S7 重算后 = 50 = 红线本身、余量为 0** —— 任何一处漏算即破线。故**「内容约束 + 运行时预算管理器（软顶 46）」仍是必需项，不是可选优化**；且**达标不得由算式自证**，必须保留**运行态实测**（逐帧求和 `vfx.aliveParticleCounts` ≤50）作为验收依据。红线硬停 `stop(StopEmitting)` 是**最后防线**，**不是余量**。

### 3.5 「50 不够用」时的减粒子方案（若日后仍需压缩）

不是放宽红线，而是逐级减量：

- **减量 L1（每命中 -1 星）**：普通命中 3 → 2，暴击 5 → 4。省 ~4/帧。
- **减量 L2（彩带减半）**：彩带 20 → 12（拉长条带长度补偿观感）。省 8。
- **减量 L3（星星爆并入彩带）**：E6 取消，星星用彩带里 3 条改贴图。省 8。
- **减量 L4（末端演出改序列帧）**：彩带整体改 **1 张 24 帧序列帧 Sprite**（0 粒子），只保留 E2/E2′/E3 真粒子。省 28。
- **最省形态**：真粒子只剩 E2/E2′/E3，峰值 ≈ S4 = **16**，远低于 50。终结演出全部走序列帧。

> **推荐**：MVP 先按 3.2 的 50 额定 + 3.4 管理器落地；若提审时平台实测 50 仍紧张，直接跳到「减量 L4」，把终结演出序列帧化——性能最稳、像素感最强。

## 四、内置 VFX 模板选用方案

### 4.1 10 个内置模板逐项判定

| 内置模板 | 本项目用否 | 用途 / 理由 |
|---|---|---|
| **Basic Particles** | ✅ **主力** | 命中星、暴怒脉冲、破盾碎片、彩带/星爆。billboard 由贴图决定形态，**换 `MainTexture` 即得像素粒子**，成本最低 |
| Physics Particles | ❌ | 3D 球体+物理，非像素、非 2D 平面，且项目禁实时物理 |
| Fire Particles | ❌ | 火焰自带「燃烧/暴力」语义，且带内置彩色贴图，DB16 与去暴力化都不符 |
| Rain / Snow | ❌ | 环境模板，本特效无天气需求（L1 留空） |
| **Explosion Particles** | ❌ | 「爆炸」语义与去暴力化冲突（击杀要彩带不要爆炸）；自带彩色贴图难锁 DB16 |
| **Firework Particles** | ⚠️ **不用**（虽形似彩带） | 见 4.3，语义与配色风险 |
| Fog Particles | ❌ | 官方明确「不要默认当成品烟雾用」；本特效无雾需求 |
| Lightning Particles | ❌ | 无需求 |
| Turbulence Particles | ❌ | 无需求（湍流用于氛围，会占粒子且非像素） |
| ParticleEmitter2D | ❌ **禁用** | **官方路由明确：仅适用 2D 流体/液体（水/黏液），不是火花/碎片/星星的通用发射器** |

> ⚠️ **对任务书的一处技术更正**：任务书写「哪些必须自制（`ParticleEmitter2D`）」——**这是个误用**。`ParticleEmitter2D` 是**2D 流体**组件，用它做像素星会在物理表现（汇聚/流动/碰撞）上跑偏。像素粒子应走「**Basic Particles + DB16 像素贴图**」，需要自定义运动时走 **VFXAuthoring（`.vfxsrc` V4）**。已同步给 tech-architect。

### 4.2 让内置模板「服从 DB16 与像素风」——可行，做法如下

**结论：可行。** 内置模板自带贴图是彩色软边 PNG（默认 `USE_TEX_ALPHA=1`，不换贴图会渲成方块/软点）。服从像素风的唯一必要动作是**整体替换粒子贴图 + 锁色**：

1. **换贴图（严格按官方顺序）**：`vfx.stop()` 清旧粒子 → `asset.setTexture("MainTexture", tex)` → `vfx.play()`（官方明写：swap `MainTexture` 前必须先 `stop()`，否则旧粒子不清）。贴图源用**隐藏的 `Screen Image` 做 TexHolder**（官方 pattern，GUID 走 `@serializeProperty`），**不要每颗粒子单独贴图**。换完即「像素星」。
2. **锁色**：贴图**逐像素量化到 DB16**，alpha 用 0/255 二值（硬边，无羽化）。粒子颜色 = 贴图颜色，模板不再引入色板外色。
3. **锁形态**：贴图硬边（Nearest），单张 8×8 / 16×16 逻辑像素，×整数倍导 512×512。
4. **锁尺寸**：不受 `renderScale` 任意放大；只走贴图的整数倍缩放。
5. **发光**：黑底贴图在 frag 末尾 `color0 = vec4(tint*alpha, 0.0)` 抠黑→亮部发光（如需 glow）；色用 DB16 值。

**可行性边界（诚实说明）**：
- ✅ **可保证**：贴图与颜色 100% DB16 + 像素硬边。
- ⚠️ **不能保证**：模板**粒子的运动/旋转是连续的**（平滑插值），做不到「逐整数像素跳格」的复古运动感。对 **≤8px 的快速小星**影响可忽略；**若终审要求粒子也「像素步进」**，则该发射器必须改 **VFXAuthoring（StandardQuad + 自定义 shader 量化运动）**——这是一条明确的升级路径，非当前 MVP 必需。

### 4.3 为什么击杀**不用** Firework/Explosion 模板

| 模板 | 判定 | 理由 |
|---|---|---|
| Firework Particles | **不用** | ① 语义是「烟花/爆」，与「去暴力化认输」气质冲突；② 自带多色，锁 DB16 需整贴图替换，成本 = 不如直接用 Basic；③ 观感「炸开」易被审读成暴力 |
| Explosion Particles | **不用** | 同上，且「爆炸」是击杀演出的**明确禁忌语** |

**替代**：击杀演出（V17/V18）= **Basic Particles ×2 发射器**（一个出彩带条贴图、一个出星贴图），同帧 burst 28 个 → 既是「彩带 + 星」，又完全 DB16、完全去暴力化。

### 4.4 必须自制的部分

- **DB16 像素粒子贴图**（星 / 碎片 / 彩带条）：无论走 Basic 换贴图还是 VFXAuthoring，**贴图必须自制**（内置模板无像素贴图）。这是本特效特效侧唯一的「原创美术资产」。
- **若启用运动像素步进** → `VFXAuthoring` 的 `StandardQuad`（自定 shader 量化）或 `StandardMesh`（彩带可用小矩形 mesh 增强翻飞感）。MVP 不做。

## 六、★ 打击感（Game Juice）设计

### 6.1 微顿帧 hitstop

| 情形 | 时长 | 触发时机 |
|---|---|---|
| 普通命中 | **3 逻辑帧 = 50ms** | 命中判定帧，所有反馈 spawn 之后 |
| 暴击 / 破盾核心 | **4 逻辑帧 = 67ms** | 同上 |
| 破盾成功 | **5 逻辑帧 = 83ms** | 核心点被打破帧 |
| 击杀（HP 归零） | **0 帧 = 0ms**（不顿帧） | 让终结演出流畅播完，不打断 |

> **口径统一（v1.2）**：全部取 **60fps 整数帧**（50 / 67 / 83ms），恢复点落在帧边界 —— `AnimatedTextureProvider.pause()` 的 `resume()` 在整帧更稳；40ms（≈2.4 帧）这种非整帧值**废弃**。与 `animation-spec` 的硬对齐点 `hitstopMs=50`（普通命中）一致；**已与 audio-director（雷鸣远）、animation-director 对齐**（音效 140/250ms > 上限 83ms，不受影响）。
> **防顿帧锁死（animation-director 裁定）**：**连击 3 发内不叠加 hitstop** —— 4 发/秒连射时只在首个命中顿帧，避免每发都冻 → 顿帧锁死/抽搐。
> **已裁定（team-lead）：hitstop 锁死 4 档** —— 普通 **50** / 暴击·核心 **67** / 破盾 **83** / 击杀 **0**。67ms **不并入** 50ms：它是「暴击/打核心点（伤害 120）比普通（80）更重」的**单调递增手感阶梯**（50→67→83），且 `implement-plan` L239/L243 与 `animation-spec §3.3` 已按 4 档落地。

**实现约束（关键，已与 tech-architect 定稿）**：hitstop **只冻结 Boss 动画与玩家输入**，**不得冻结 L4 特效层**。否则闪白只闪到第 1 帧就被冻住、粒子卡顿。
经柯桥良核 `APJS.d.ts`：**本引擎没有全局 timeScale / unscaledDeltaTime**（只有 `Physics2D.timeSpeed` / `Physics3D.timeScale`，且仅缩放物理模拟，不影响动画/VFX）。因此**方案②被否决，只走方案①**，实现如下：
- **冻结 Boss 动画**：用 `AnimatedTextureProvider.pause()` / `resume()`（该类有 `play/pause/resume/stop/reset`；`loopCount=0` 亦可禁用播放）。**不要去改 timeScale**。
- **屏蔽射击输入**：全局 Touch 回调里加 `hitstopTimer > 0` 守卫，直接 `return`。
- **L4 命中特效层照常跑 `onUpdate`**：因未动全局时间，粒子/闪白不受影响 → 这就是「闪白不被冻住」的落地方式。
- Boss 的脚本位移/缩放（Tween）顿帧时**跳过 `onUpdate` 推进**即可。
- **前提**：Boss 帧动画必须是 **AnimatedTexture（TextureSequence）** 才有 provider 可 pause（已同步动画侧）。

### 6.2 屏幕震动 / ScreenShake

| 事件 | 幅度（屏幕 px @参考投影128，单帧最大） | 时长 | 衰减 | 备注 |
|---|---|---|---|---|

| 破盾 | **3.0** | 0.20s | 二次衰减 | 明显「咔」 |
| 暴怒切换 | **4.0** | 0.35s | 二次衰减 | 阶段最强，仅此一处到 4 |
| 认输演出 | **3.0** | 0.30s | 二次衰减 | 喜庆感 |
| 失败逃跑 | **2.0** | 0.25s | 线性 | 不吓人 |

> **★ 本表 px 列 = 全项目震屏幅度引用源（勿单独改量级）**：`implement-plan §2.4` 的 k 表**直接取本列值**，按 `k = px / 128` 折算成「Boss 世界高比例」（六档 0.5/1.5/3/4/3/2 px → 0.4%/1.2%/2.3%/3.0%/2.3%/1.6%），落到主程纯常量模块 `constants/ShakeAmp.ts`。**调整本列 = 静默改全项目震屏幅度（两处同步漂）** → 要改必须**先知会 tech-architect + lead-programmer**。

> **★ 本表 = 全项目「受击 / 震屏抖动」唯一来源（幅度 + 时长 + 衰减）**（team-lead v1.9：震屏视作**一个特效**）。**但「原 V6（Boss 本体 ±2px）已并除」是 ⚠️ 条件性、待验证的**——并轨依赖「`ContentRoot` 2D 偏移**经父子传导带动 3D Boss**」这一**未实测前提**：`node-plan §1.2` L133 明记**「不可依赖父子传导」**（3D 世界锚定 transform 可能被 AR 追踪每帧覆写）；`node-plan §7` 第 9 项真机 A/B **未做**（已升 🔴 阻断性前置），文档证据**倾向「不跟随」**。**判「跟随」⇒ 并轨成立、路① 永久废除；判「不跟随」⇒ Boss 完全不抖 ⇒ 必须恢复路①**（Boss 世界空间加法位移，复用同一 `ShakeAmp.ts` 值，成本可控）。**冻结前须先判**（同 `node-plan §7-9` / `tech-spec §2.8 ⑥/⑦`）。**时长**不另设源——`animation-spec §7.2` 是「有动画触发帧」的事件索引，其幅度/时长均指回本表。

**防晕硬规则（必须遵守）**
1. **单帧屏幕位移 ≤ 4px**（≈ Boss 世界高 3.0%，**分母同 §6.2 k 表 = 参考投影 128**：4/128）；本项目最大仅暴怒 4px。
2. **只平移，绝不旋转**（旋转摇镜头最易致晕）。
3. **不叠加**：新震动**覆盖**旧震动（取较大值），不做向量相加。
4. **单调衰减**，时长 ≤ 0.35s，无回弹抖动。
5. 后坐力（V2）与命中震动**分离**：后坐力属开火（L3），命中震动属命中（L4），两者幅度**分别计算但不叠加到同一帧超 4px**——命中帧若同时开火，取二者较大值。
6. 震动作用对象 = **专用 `ContentRoot`**（2D Scene Object，挂在 2D Camera 下；L2–L5 挂其下），震动 = 偏移 `ContentRoot.ScreenTransform.anchoredPosition`。**禁动真 Camera**（避免透传错位 + 复用共享 Camera 风险）。**ContentRoot 是变换父节点、不是图层**，render group 仍独立控制排序，**不占 6 层额度**。 ⚠️ **作用点待验证（v2.2）**：`ContentRoot` 对 L2/Boss 是否只是**结构归属**（2D 偏移能否带动 3D 世界锚定的 Boss）**未实测**；按 `tech-spec §2.8 ⑥/⑦`，Boss 抖动应在 **Boss 世界空间**施加、`ContentRoot` 2D 震动只服务 **L3/L5（幅度减半）**。**详见本节 ★ 脚注**（判「不跟随」⇒ 恢复路①）。

### 6.3 闪白

- **实现**：**材质 albedo 硬切**（非 Tween 插值，避免中间色超标）——命中帧置 `#deeed6`，**第 2 帧复位**（1–2 帧）。
- **帧数**：普通 1 帧（16.7ms）；暴击/破盾 2 帧（33.3ms）。
- **替代方案**（若材质不可改）：L2 叠一层「Boss 白色剪影 Sprite」可见 2 帧。二选一，不给两个。
- **禁忌**：不做渐进淡入淡出（会出 DB16 外的灰阶）。

### 6.4 伤害数字

| 项 | 普通（80） | 暴击（120） |
|---|---|---|
| 颜色 | `#deeed6`（近白） | `#dad45e`（黄） |

| 淡出 | 末 0.15s 线性淡出 | 末 0.18s |

**连击叠字策略（避免数字堆满屏幕）**
1. **合并计时器**：距上一次命中 **< 120ms** 时**不开新数字**，把本次伤害**累加**进当前数字（显示累计值）并**重弹一下**（scale 回 1.2）。连射 4/s 时玩家看到的是**一个跳动的累计数字**，而非每秒 4 个。
2. **对象池 = 3**：超过 3 个并发需求时，复用最旧的一个（覆盖）。
3. **错位**：每个新数字在**命中点的屏幕投影点**（屏幕口径，非世界坐标）基础上随机 ±8px（屏幕 px）偏移，并左右交替微偏，减少重叠（但仍合并为主要策略）。
4. **位数限制**：最多 4 位；暴击另用「!」标记不占位。
5. **禁区**：数字不可飘入**准星中心圆**与**底部 180px 录制按钮禁区**。

## 八、时效对齐表（以「命中」为例，精确到帧/毫秒）

> 基准 60fps（16.67ms/帧）；以平台实际录制帧率为准，括号内为 30fps 近似。
> **同帧触发实现**：命中判定进入同一确定性函数 `onHit(isCrit)`，下列②~⑦在**同一帧同一调用栈**内顺序执行 → 视觉延迟 **0 帧**。

| 帧 | 时刻 | 动画（animation-director） | 特效（vfx-director） | 音效（audio-director） |
|---|---|---|---|---|
| **f0** | **0ms** | Boss 切「受击」序列帧第 1 帧 | ②闪白置白 ③像素星 emit ④伤害数字 spawn ⑤震动触发 | **sfx_hit play()（同帧交棒）** |
| f1 | 16.7ms（30fps: f0） | 受击动画第 2 帧 / 抖动 onset | 闪白第 2 帧（暴击）；星扩散；数字上飘第 1 帧 | — |
| f2 | 33.3ms（30fps: f1） | 受击动画推进 | 闪白复位（普通）；hitmarker 外散 | — |
| f3 | 50ms（30fps: f1） | 受击动画推进 | 抖动衰减中 | — |
| **f2–f3** | **50ms（3 帧）** | **hitstop 结束，恢复时间流** | （hitstop 期间 L4 不受影响，正常播） | — |
| f3–f13 | 50–217ms | 受击动画收尾 | 星存活至寿命末（0.22s）；hitmarker 淡出 | — |
| f13–f18 | 217–300ms | — | 暴击星（0.28s）收尾 | — |
| f36 | 600ms | — | 普通数字回收 | — |

**特权说明（"同帧"到底怎么做）**
1. **视觉 0 帧延迟**：②~⑥全部在 `onHit()` 内**同步调用**（`emit()`/`setEnabledInHierarchy(true)`/`play()`/位移赋值），不排帧、不 setTimeout。
2. **音效同帧交棒**：`audio.play()` 与粒子 `emit()` 在**同一帧同一函数**内调用；受音频硬件缓冲影响，听觉延迟 < 30ms。**视觉与音效的启动帧差 = 0 帧**。
   - **强化（与 audio-director 对齐）**：命中音必须与 **hitstop 开始的同帧入队** —— 否则玩家主观顺序变成「画面先停住 → 才听到啪」，打击感掉档。
   - **音效绝不挂在动画事件（帧事件）上** —— 帧事件时序可能晚 1–2 帧（33–66ms）→ 发飘；音效一律由程序在判定帧直接调用。
3. **hitstop 与特效的解耦**（重申）：hitstop 冻结的是 Boss 动画 + 输入，**不是 L4 特效**；否则闪白/粒子被冻住 → 见 6.1 实现约束。
4. **时序交接点（给 audio-director）**：命中音与「像素星 emit」同帧；连击叠音以「合并计时器 120ms」为节拍单位（与 6.4 叠字同一计时器，音画同拍）。
5. **对齐点引用源（v1.2b 更新）**：本文**不引用动画帧事件（`onAlignPoint` 已作废）**；下表及其它非命中特效（V11/V14/V15/V16/V20 等）的触发时刻，一律由 **`BossAnimPlayer` 的播放时钟按 `animation-spec §5.2「时间偏移规则」` 派发**（与对应视觉帧同帧、hitstop 期间自动顺延），与音效同策（§8 说明 2 第 2 条）。

## 十、特效侧 AI 生成可行性（像塑 MCP `generate_image` / `generate_assets_batch`）

**问题**：像素风粒子贴图能否 AI 生成并服从 DB16？

**结论：AI 可作「创意源」，不能作「最终资产」——必须过 DB16 量化闸门。**

理由与风险：
1. AI 图像模型**输出抗锯齿、渐变、色板不受控**，**无法保证恰好 16 色 DB16**，像素边缘常带半透明羽化。
2. 直接入库 = 违反「DB16 禁止超出」「禁羽化/双线性」两条死规则。

**推荐做法（两步管线）**
1. **AI 生成候选**（`generate_image`）：提示词固定为
   `pixel art sprite, 16-color palette, hard edges, no anti-aliasing, no gradient, transparent background, centered, 32x32`，出多张选形。
2. **强制后处理（必做，不可省）**：
   a. 尺寸归一到 **8×8 / 16×16** 逻辑像素；
   b. **逐像素量化到最近 DB16 色**（脚本：DB16 调色板做 nearest-color map）；
   c. **alpha 二值化**（>0 即 255，消除羽化）；
   d. **×整数倍 Nearest 放大到 512×512** 导出。
3. **入库前人工比对**：确认无 DB16 外色、无羽化。

**更稳的替代（推荐用于核心小贴图）**：**程序化手绘**——用一段脚本按 DB16 直接画出 8×8 星、16×16 碎片、16×16 彩带条。确定性 100% 合规、体积极小（<1KB 逻辑）、无 AI 不确定性。**AI 只用于「形」的灵感，最终像素图建议手绘/程序生成。**

**判定**：**AI 生成可行但非最优；本特效的 4 张核心粒子贴图建议手绘/程序生成，AI 仅出概念参考。**
