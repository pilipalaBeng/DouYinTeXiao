# ar-boss-raid · 真 3D 空间玩法改造方案（v3）

作者确认时间：2026-10-15。确认依据：作者针对本方案的 4 项决策回复「1.可以听你的 2.随机漂移 3.看你，你感觉有用就留着，没用就删掉 4.那就稳点」。

## 1. 最终效果

Boss（像素飞行能量核心）成为**真实悬浮在用户所处空间中的 3D 对象**。用户转动手机四处观察时，Boss 在画面中相应移动、进出视野——而不是像现状那样在屏幕内自己漂。把 Boss 转进屏幕中央的固定准星即可长按发射弩箭命中，走完试探/活跃/护盾/结算全流程。

现状问题：`Boss主体` 是 2D `ScreenTransform + Image`，脚本 `updateBoss3D()` 实际是在**屏幕空间**用正弦波+视差滑动贴图，转动手机不产生真实视差。

## 2. 场景与资产

### 场景组成

- **新增「Boss空间体」**：3D `Image` 对象（世界空间图片平面），置于 ARTracking 渲染组、世界坐标；承载 Boss 像素纹理。
  - 选型说明：方案初稿写 `Plane`，落地时发现 Boss 纹理为**透明背景 PNG**，`Plane` 需自建 `Unlit` 材质并配 `_EnableAlphaTest`/`_AlbedoCutoff`，而工程内无材质资源；`Image` 原生支持透明且视觉结果相同，属等价实现，故改用 `Image`。场景内 Boss 是唯一 3D 前景物，不存在 `Image` 透明队列互盖的风险。
- **复用 `AR摄像机`（s7）**：已带 `DeviceTracker`，`trackingMode = World`，转角即相机转向。
- **原 2D `Boss主体`（s16）删除**：改为 3D 后不再被消费，属冗余对象。其纹理 r11 继续复用。
- **准星 / HUD / 战弩 保持 2D 屏幕层**：本就应固定在屏幕上。
- **护盾覆盖、护盾核心、Boss出战牌、Boss头像、命中星爆、伤害数字**：保持 2D，由脚本用 Boss 的**投影屏幕坐标**逐帧驱动位置（稳定、不引入额外 3D 材质风险）。
- 背景：摄像头透传，不新增全屏层。

## 3. 交互与状态

- **初始**：Boss 在用户前方随机方位生成，沿球壳做随机漂移（速度含轻微扰动），在用户周围 2~6 米范围内活动。HUD 显示稳定 2400 / 30s。
- **转动手机** → 相机转向 → Boss 在画面中相应位移、可进出视野。
- **Boss 进入准星容差圈（半径 122px）** → 准星高亮 + 对准提示音，此时可命中。
- **长按屏幕** → 每 250ms 发射一枚弩箭（弩身播放拉弦→击发→回位），命中则稳定值 -80，护盾核心 -120。
- **表情能量波**（眨眼/张嘴）→ -160。
- **阶段推进**：稳定值 ≤1584 进活跃（振翅加速+波纹），≤792 进护盾（累计 3 次核心同步破盾），破盾后 2s 校准窗口，沿用现有逻辑不改。
- **Boss 转到相机背后或超出投影范围时**：2D 跟随物随之隐藏，准星判定失效（视为不可命中）。
- **结算**：警报解除或超时进入结算界面，沿用现有逻辑；再开拍则重置。

## 4. 验收方式

- [ ] 真机转动手机：Boss 在画面中的位置随手机朝向变化，能转出/转进视野。
- [ ] 把 Boss 转进准星：准星高亮出现，对准提示音播出。
- [ ] 长按发射：弩箭飞向 Boss，命中后稳定值下降、连击累加。
- [ ] 初始态：无残留对象、无模板残留、HUD 为 2400/30s。
- [ ] `run_otsc_check` 无编译错误。

## 5. 已知限制

- **PC 预览无 SLAM**（项目 README §八 实测）：编辑器内 AR 相机姿态随机、约 4s 收敛，**3D 手感无法在编辑器验证，必须真机**。编辑器内只能验证链路连通与静态结构。
- `worldToScreenPoint` 返回的是**左下原点像素坐标**，与 2D UI 的左上原点不同，需翻转 y。
