## 0. v1 → v2 变更摘要

| 项 | v1 | v2 |
|---|---|---|
| 瞄准方式 | 触摸拖动准星 | AR 相机跟随设备姿态；转手机把 Boss 转进屏幕中央准星 |
| 相机 | 2D 正交相机 | AR Camera + DeviceTracker（trackingMode = World） |
| Boss 载体 | 2D Screen Image | 3D Image（world-space），入 ARTracking 渲染组 |
| 命中判定 | TouchUtils.isScreenPointOnImage | camera.worldToViewportPoint(bossPos) 与屏幕中心比距离 |
| 头像 | Image Picker (Head)（本版像塑无此能力） | 预设像素头像选择器（6 选 1） |

保留不变：血条 HUD、DB16 像素化流水线（tools/pixelize.py）、包体结论（3.2 KB/帧，阈值 26.8 KB）、命中音效、250 ms 开火闸门、RecordStart 开拍重置。

## 1. 最终效果

手机摄像头实时画面为底。一个 16 色像素风大 Boss 锚定在真实空间中（约屏高 55%），玩家需转动（并抬起）手机在四周扫视，把 Boss 转到屏幕正中的准星上才能开火。Boss 头顶挂一枚玩家从 6 个预设像素头像中选出的头像。顶部像素血条、屏幕中央准星。按住开火，命中掉血、闪白、顿帧、轻震、出声。血量降到阈值依次进入暴怒、护盾、假死，最终认输演出 + WIN 结算卡。

像素规格（项目宪法死参数）：逻辑画布 64×64（大元素 128）、导出 512×512 透明 PNG、固定 DB16 十六色、Nearest 采样、图层 ≤6、粒子 ≤50、包体 ≤2MB、单动作序列帧 ≤24。

## 2. 场景与资产

**场景组成**
- **ARTracking 渲染组**（新增）：add_builtin_object('AR Plane') 自动建出 AR Plane + AR Camera（含 Camera + DeviceTracker）。Boss 置于本组内的 3D 空间。
- **Boss 本体**：3D Image 承载像素序列帧贴图，锚定真实空间；11 动作状态机。
- **头像位**：Boss 头顶挂点下的 3D 子对象，贴所选预设头像；外套像素相框。
- **2D 前景组**（沿用）：血条 HUD（底槽 + 填充）、屏幕中央准星。
- **特效层**：3D 粒子（尘土 / 像素星 / 彩带 / 盾碎片），总数 ≤50。
- **状态页父对象**：结算卡（WIN / LOSE），独立父对象。
- **音频对象**（沿用“音乐”渲染组）：BGM ×2 + 音效 ×24。

**资产清单**（合计约 116 件 + 6 预设头像）

| 资产 | 来源 | 用途与要求 |
|---|---|---|
| Boss 序列帧（11 动作 / 47 帧） | 待生成 | 128 → 512 导出；按动作分目录 |
| 小怪 4 帧 + 枪口闪光 2 帧 | 待生成 | 同上 |
| 预设像素头像 ×6 | 待生成 | 64×64 逻辑，DB16 |
| Boss 静态部件（眼睛叠层、护盾、相框、旗子） | 待生成 | 512×512 透明 PNG，DB16 |
| HUD 部件（血条底槽/填充、准星、按钮底板、结算卡面板） | 待生成 | 像素风；文案走独立 2D Text |
| 粒子贴图 | 待生成 | 小尺寸透明 PNG |
| 音效 24 + BGM 2 | 待生成 | 仅 .mp3 |

## 3. 交互与状态

- 初始：Boss 待机锚定于空间、满血 2400、准星固定屏幕正中、血条满格；开拍即重置。
- **瞄准**：转动手机 → AR 相机朝向变 → Boss 在屏幕上相对滑动；Boss 投影进入准星容差框即为“瞄准中”。
- 射击：按住屏幕即持续开火，每 250 ms 一发（严格 4 发/秒）。
- 命中判定：camera.worldToViewportPoint(bossWorldPos)，与屏幕中心 (0.5, 0.5) 比较 x/y 距离，且 z > 0（在相机前方）。
- 命中反馈：掉血 + 闪白 1–2 帧 + hitstop（普通 50 ms / 暴击 67 ms / 破盾 83 ms）+ 轻震 + 音效 + 粒子。
- 阶段推进：66% 暴怒 → 33% 开护盾（核心点 3 次破盾，回盾上限 2 轮，护盾期 HP 冻结）→ 15% 假死。
- 胜利：血量归零 → 旗子脱手 600 ms → 落地 950 ms 彩带星爆 → 1100 ms 弹 WIN 卡。
- 失败/超时：LOSE 卡。
- 头像选择：开局弹出 6 选 1 面板，选定后收起并贴到 Boss 头顶。

## 4. 验收方式

- [ ] AR 场景建立：ARTracking 渲染组存在，AR Camera 带 DeviceTracker；预览不黑屏、编译通过。
- [ ] 初始态：Boss 与血条完整可见，无元素落进底部录制按钮区。
- [ ] **转手机：Boss 在屏幕上产生相对位移；转出视野后不可见，转回可见。**
- [ ] **Boss 进入准星容差框内开火 → 命中；Boss 转出框外开火 → 不命中。**
- [ ] 头像：6 选 1 面板可选，选定后头像出现在 Boss 头顶。
- [ ] 血量阈值处：暴怒 / 护盾 / 假死依次触发，HP 与血条同步。
- [ ] 击杀：认输演出四段时序正确，WIN 卡弹出。
- [ ] 编译与包体：run_otsc_check 通过；Σ artifactFileSize ≤ 2 MB。

## 5. 执行策略

1. **先验证 AR 能力可挂**：add_builtin_object('AR Plane') 试挂，确认本版本编辑器真的支持 DeviceTracker（此前有 Image Picker 的“知识库有、编辑器无”前科）。失败则立即回报并退回触摸方案。
2. **搭 AR 空间最小链路**：Boss 一个动作 + 准星（屏幕中央）+ 一次命中反馈 + 一个音效，跑通「转手机 → 转进准星 → 开火 → 命中 → 掉血」。
3. **再补齐**：6 预设头像选择器、全 11 动作、四阶段、护盾、假死、认输演出、结算卡、全部音频与粒子。

## 6. 已知风险

- AR 追踪依赖真机视觉惯导（SLAM）：PC 预览只能验“建得出、编译过”，**最终手感必须真机验证**。
- World 模式对环境有要求（地面有纹理、光线充足）；若真机不稳，可切 trackingMode = Orientation（仅水平，更省，但无法抬头找高处目标）。
- AR 追踪有性能开销，需关注真机帧率。
