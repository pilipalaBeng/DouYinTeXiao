# 画面效果

当用户要求作用于屏幕或相机输出的视觉效果时使用此 skill，包括 blur、bloom、vignette、chromatic aberration、distortion、grain、edge detection、color grading、mask，或由手势/关键点驱动的全屏反馈。

## 工具

使用 `effect_house_toolbox`，并设置 `tool_name: "sceneOps"`。把 PostProcess 作为普通场景操作放入 `payload.ops[]`，并设置 `type: "PostProcess"`。

支持的场景操作：
- `op: "add"`：通过 Agent sceneOps entity config 创建 PostProcess 场景对象，并向 `postProcessList` 添加一个效果。必须提供 `effectType`。
- `op: "modify"`：更新已有 PostProcess 组件。当前编辑态修改能力仅限于 Custom 材质重新绑定。
- 对已有 PostProcess 场景对象使用 `op: "modify"`，并提供 `id` 或 `guid` + `materialGuid`：绑定或重新绑定 Custom PostProcess 材质。如果省略 `effectType`，工具会按 `Custom` 处理。
- `op: "remove"`：通过 `id` 或 `guid` 移除已有 PostProcess 场景对象，与 Image/Text/Audio 相同。
- 运行时脚本的材质/纹理字段通过 `setupGameScript` 的 `resourceBindings` 参数绑定，不通过 `sceneOps`。`sceneOps` 只用于 PostProcess 组件创建/配置。

支持的 effect type：
`Bloom`, `Fxaa`, `ChromaticAberration`, `Distort`, `Grain`, `Vignette`, `LensFlare`, `MotionBlur`, `BokehBlur`, `Custom`.

能力语义覆盖发光、边缘眩光、扭曲、粒感、暗角、散景模糊、运动模糊和自定义画面效果。`Bling` 闪光也归入本能力，但它是独立组件，不是 `PostProcess.effectType`；不要把 Bling 当作上述 effect type 传给 `sceneOps`。

PostProcess `sceneOps` 字段：

唯一公开的 operation 名称是普通场景操作名：`add`、`modify` 和 `remove`。

对于 `op: "add"`，`id` 不只是工具内部标签。编辑器会把创建出的 PostProcess SceneObject 重命名为这个值，行为与 Image/Text 一致。运行时脚本应使用这个 `id` 调用 `this.add.postProcess(id)`。

视觉特效工作流创建 PostProcess 时，`id` 必须逐字使用 `Assets/design_brief.md` 中确定的中文名称，例如 `局部水波后处理`。不要生成 `custom-post-process`、`post-process-1` 或拼音名称。运行时脚本引用同一对象时继续使用这份中文 `id` 字符串，不另设英文别名。

## 内置效果
内置效果会对全屏生效，需要只对局部生效时不要使用。

对于内置效果，调用：
不要在编辑态使用 `sceneOps` 修改内置 PostProcess 参数值。`sceneOps` 有意不向 Agent 暴露原始 PostProcess 组件 `properties`。如果效果需要调节数值或动画，生成运行时脚本，并按下文直接更新 APJS PostProcess effect accessor。

创作约束：
- 通过 `sceneOps` PostProcess `add` 添加效果；不要依赖 `modify` 或直接修改原始 `postProcessList` 来后续添加内置效果。
- Agent 面向的 `effectType` 值是可读字符串，但编辑器侧 `postProcessList` 存储的是 OrionPackages 中的数值型 `PostProcessEffectType` 枚举值。
- 如果 `pp.bloom` / `pp.vignette` / `pp.distort` 等运行时 accessor 为 null，说明该效果没有被编辑态 PostProcess 设置实例化。应修复编辑态设置，不要尝试在脚本中创建该子效果。
- 每种效果在一个 PostProcess 组件的 effect list 中最多出现一次。要安全地展示多个独立效果，应显式创建/配置所需效果，而不是猜测 list mutation。
- 不要传入或设置 `pVignetteEnable`、`custom.enabled` 等编辑态 enable 字段；`sceneOps add` 写入 `postProcessList`，`sceneOps modify` 只绑定 Custom 材质。如果脚本需要切换效果，使用直接 APJS 运行时访问。

## Custom 材质

对于自定义屏幕空间 Shader：

1. 阅读 `.agent/skills/effect-abilities/material-authoring/材质编写.md`。
2. 使用 `materialAsset.create` 创建完整且经过验证的 OMTL。
3. 创建或配置 PostProcess 前，确认材质已成功编译并导入。优先信任 command-level `compile_error`；只有没有 `compile_error` 且 `compiled === true` / compile status 健康时才继续。如果 compile status 不明确，使用材质 GUID 调用 `materialAsset.get_compile_status`。
4. 创建组件时，用 `sceneOps` `type: "PostProcess"` / `op: "add"` 绑定；重新绑定已有组件时，用 `op: "modify"` 并传入已有 PostProcess 场景对象 `id` 或 `guid`。
5. 所有可被用户、Agent 或脚本编辑的材质属性，必须同时声明在材质 `UIPROPERTY` 块和匹配的 AUSL uniform 块中。材质仅在局部 GAN 合成场景中声明 `Default_Camera_Input`：GAN 已全屏生效，但最终只允许局部区域显示 GAN 结果时，区域内采样已处理的 `_MainTex`，区域外采样 `Default_Camera_Input` 恢复未处理相机画面。
6. 如果材质运行时需要 hand/finger/touch uniform 或运行时变化的纹理，先确认 `GameManager.ts` 已声明序列化资源字段，再在同一工作流中调用带 `resourceBindings` 的 `setupGameScript`，确保同一个材质和运行时资源分配给 `GameManager`。

如果材质已创建并编译后，PostProcess add 返回 `ALREADY_EXISTS`，不要认为工作流已完成。这只证明场景对象存在。应立即再次调用 `sceneOps`，使用 `type: "PostProcess"`、`op: "modify"`、已有 PostProcess 场景对象 `id` 或 `guid`，以及已编译的 `materialGuid`，来绑定/重新绑定 Custom 材质。

如果批量调用返回 `MIXED_POST_PROCESS_OPS`，把 PostProcess 操作拆成单独一次 `sceneOps` 调用。拆分后，确认 Custom 材质确实已绑定。如果对象此时返回 `ALREADY_EXISTS`，按上面的 `modify + materialGuid` 重新绑定流程恢复。

1. 先检查 `GameManager.ts`。在任何重试前，它必须声明与 `resourceBindings` 条目匹配的 `@serializeProperty()` 字段。

### 运行时内置效果 API

对于非 Custom 内置效果的运行时变化，生成脚本应直接访问 APJS PostProcess 组件。不存在可导入的 `./PostProcess` wrapper，也不要创建该 wrapper。如果 PostProcess 对象由 `sceneOps` 创建，使用 `op: "add"` 时的同一个 `id` 调用 `this.add.postProcess(id)`，再通过 `bloom`、`vignette`、`distort` 等 APJS accessor 访问具体效果：

不要把所有 PostProcess effect 属性都镜像到 `GameManager` 的 `@serializeProperty()` 字段。脚本 UI 暴露必须按需：
- 默认强度、按压强度、缩放量、波幅、频率、速度、衰减值等内部调节值，使用 private 字段或局部常量。
- 只有用户明确希望在编辑器中调节的具体控制项，才添加 `@serializeProperty()`。
- 对简单交互，不暴露任何数值控制，直接在代码中设置 APJS effect 属性。

其它效果使用相同模式：把 `pp.bloom` 替换为
`pp.vignette` / `pp.distort` / `pp.bokehBlur` / 等。每个 accessor 的
类型都是对应的 `PostEffect` 子类，并有各自的属性表面。
