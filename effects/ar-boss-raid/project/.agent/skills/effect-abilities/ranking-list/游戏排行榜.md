# 游戏排行榜

## 能力描述

展示跨用户的游戏成绩排名，可使用分数、用时等游戏成绩作为排行口径。个人排行榜支持升序或降序，区域排行榜按聚合成绩从高到低排列。

游戏排行榜通过同一个功能配置“排行榜类型”和对应的“排行方式”：

- **个人排行榜**：排名主体是单个用户。可选择全国排行，在使用该特效的全部用户中比较个人成绩；也可选择好友排行，在当前用户的好友范围内比较个人成绩。
- **区域排行榜**：排名主体是区域或学校，榜单成绩为该分组内用户成绩的聚合结果，并按聚合成绩从高到低排名。可按省份、城市、区县或学校进行聚合和排名。

选择时先确定排名主体：比较用户个人成绩时选择个人排行榜，再根据用户期望的竞争范围选择全国或好友；比较地域或学校的整体成绩时选择区域排行榜，再根据玩法所需的分组粒度选择省份、城市、区县或学校。用户仅提出“排行榜”时，先向用户确认排行榜类型和排行方式这两级配置。

场景搭建阶段通过 `add` 或 `modify` 写入排行榜配置。新增时可使用以下结构，修改时沿用相同的 `general.properties`：

```json
{
  "op": "add",
  "type": "General",
  "id": "游戏排行榜",
  "positionMode": "absolute",
  "x": 360,
  "y": 609,
  "width": 512,
  "height": 622,
  "general": {
    "kind": "GameRankingListJS",
    "properties": {
      "listCategory": 0,
      "listType": 0,
      "minScore": 0,
      "maxScore": 999,
      "scoreUnit": "分",
      "sortType": 0
    }
  }
}
```

- `listCategory`：`0` 为个人排行榜，`1` 为区域排行榜。
- `listType`：个人排行榜使用 `0` 全国或 `1` 好友；区域排行榜使用 `2` 省份、`3` 城市、`4` 区县或 `5` 学校。
- `minScore`、`maxScore`：成绩允许范围；`scoreUnit`：展示单位，如“分”“秒”“米”或“ms”。
- `sortType`：`0` 为降序，`1` 为升序；区域排行榜使用降序。
- `positionMode`、`x`、`y`、`width`、`height` 等布局字段放在场景对象顶层，`general.properties` 只承载排行榜功能配置。

## 适用场景

核心玩法会产出明确、可量化且能用于比较的游戏成绩时，默认加入游戏排行榜，并在结算阶段提交最终成绩。常见指标包括：

- 得到多少分、累计多少积分或达到多高分数；
- 完成关卡、竞速或解谜耗时多少秒；
- 生存、防守、平衡或躲避玩法中坚持多少秒；
- 击倒、消除、命中、收集或完成多少个目标；
- 到达多少层、通过多少关或完成多少轮；
- 连击数、准确率、完成度、剩余生命等可转换为数值的游戏表现。

高分、数量、层数等“数值越大成绩越好”的指标使用降序排行；耗时等“数值越小成绩越好”的指标使用升序排行。排行榜用于跨用户比较最终游戏成绩；当前局内的实时分数仍可单独展示。按签到次数、参与次数或连续参与天数排名时使用「打卡排行榜」。

## 展示时机

游戏排行榜开始时默认隐藏，游戏进行过程中保持隐藏。游戏结束进入结算阶段时，先写入本轮最终成绩，再展示排行榜；开始新一轮游戏时重新隐藏。
