# 声音挑战创作规划

> 读取时机：Draft 确认后，音量、音高或关键词直接驱动核心状态、反馈或结果时读取
> 职责边界：只补充声音输入、判定、反馈与降级的 Brief；runtime API、依赖和检测器生命周期由对应能力 Skill 与 `game2d-engine` 实现

## 适用判断

音量、音高或关键词直接驱动角色、进度、成功条件或结果时使用，例如喊叫蓄力、吹气推进、唱准目标音区或说出口令触发动作。普通 BGM、点击音效、语音播报和只播放音频的游戏不使用本 Reference。

## 创作决策

### 主输入路径

- **volume**：适合喊叫、吹气、蓄力和声音强弱挑战；规划归一化强度、有效持续时间和反馈曲线。
- **pitch**：适合唱歌、音高控制和目标音区挑战；规划有效音高、目标区间、稳定命中时间和平滑反馈。
- **keyword**：适合口令、目标词和语音选择；规划目标词集合、激活阶段和命中事件。
- **combined**：两个信号都实际参与规则时使用，并分别说明职责和联合判定。

### 声音阶段

挑战型体验可使用 `准备提示 → 声音输入激活 → 实时反馈 → 达成或超时判定 → 结果反馈`；持续声音互动可使用 `准备提示 → 声音输入激活 → 实时反馈 → RecordEnd 清理`。明确检测开始、停止、有效窗口和阶段退出条件。

### 判定与反馈

- **volume**：使用归一化后的声音等级驱动能量条、火焰、蓄力或运动，持续有效输入优先于瞬时尖峰。
- **pitch**：用目标音区和稳定时长判定；无有效音高时保持等待反馈。
- **keyword**：目标词短且明确，每个阶段维护清晰的目标集合，以命中事件推进状态。
- **combined**：分别定义两个输入的职责、有效条件和联合判定。
- 实时反馈让玩家理解当前输入与目标的关系，结果反馈与判定强度或命中情况一致。

### 稳定降级

- 无声音、无有效检测、超时或检测能力不可用时，进入当前体验定义的等待、提示、中性结果或保持状态。
- 无效检测值不参与计分或成功判定；辅助信号失效时只降级其反馈。
- 声音检测阶段使用克制声景，必要音效放在检测前、检测后或采用不干扰判定的短反馈。
- 声音是用户指定核心卖点时，降级保持流程稳定并保留声音玩法语义。

## Brief 补充

- `design_brief.md`：记录声音如何参与核心循环、玩家目标和总体反馈。
- `design_brief_ui.md`：规划实际存在的准备、检测、反馈和结果阶段 UI、Text、主体状态及生命周期。
- `design_brief_gamelogic.md`：在模块清单中加入主输入路径、激活窗口、有效输入、平滑或归一化、实时反馈、降级和边界处理；仅挑战型体验加入成功、超时和结果规则。

## 验收

- Draft、三份 Brief 和最终脚本选择同一种主输入路径。
- 检测开始、停止和无有效输入路径完整可达。
- volume 使用归一化输入，pitch 区分无效输入，keyword 目标与阶段一致。
- 检测不可用时稳定进入已定义提示或中性结果。
