# 通用玩法质量

> 读取时机：Draft 确认后、撰写 Brief 前，所有由 game2d-planner 处理的游戏创作固定读取
> 职责边界：只按实际机制补充输入、推进、反馈、结果、边界和 reset，不定义素材、布局或 SceneOps

## 核心闭环

- 明确玩家反复执行的核心输入，以及每次有效输入如何改变角色、目标、局面、资源、进度或结果。
- 操作型玩法的核心输入直接改变与成功判定相关的可控量，例如位置、方向、力度、轨迹、目标、时机或选择；只负责触发动作时，系统稳定提供可预判、足够宽松且不依赖偶然等待的成功机会。
- 从 RecordStart 后的稳定初态出发，保证第一次有效输入到达处理逻辑并产生可观察反馈。
- 一次操作完成后重新进入可操作状态、形成新的合法操作，或进入当前设计实际存在的结果/结束。
- 有效、无效、连续、冲突和高频输入都有唯一处理，一次输入只产生一个确定结果；以离散目标为消费单位的连续拖拽仅在进入新目标判定区时消费输入，停留在当前目标区的重复采样忽略。

## 有限等待与结束

- RecordStart 后的准备、权限、校准和倒计时在有限时间内结束；能力不可用时按当前玩法继续、降级、提示或安全结束。
- 玩法依赖动态对象时，正式开始后先创建第一组可玩对象，再启动普通生成、随机和进程变化。
- 达到完成、失败或时间耗尽条件后，在短暂收尾后进入结果；蓄力、跳跃、动画、输入锁或异步任务不能阻塞结束。
- 结果型互动从 RecordStart 后的可交互状态到达结果。只有用户或 Brief 明确规定无输入超时及其结果时，才允许兜底；否则无输入保持当前可交互状态，直到 RecordEnd。

## 推进与变化

- 过程在目标、对象组合、判定窗口、速度、间距、资源、风险、选择价值或反馈强度中选择实际适用的维度随进程变化。
- 变化服务同一个核心互动；难度或复杂度变化后仍保留可判断、可执行、可恢复的合法推进路径。

## 空间与动态内容

仅在玩法涉及移动、跳跃、滚动、镜头推进、动态生成或空间判定时应用：

- 游戏场景使用左上原点屏幕坐标：`+X` 向右，`+Y` 向下。
- 成功条件同时受位置、对象最终显示尺寸、接触点、速度、时间、加速度、轨迹、碰撞范围或判定窗口中的多个数值影响时，按玩家实际可控量、输入后轨迹与目标在判定时刻的有效区，推导首轮学习状态和最不利可生成状态的完整成功路径；仅存在非危险目标、只在理想组合下可达或依赖无限等待偶然重合，不算合法推进。
- 规划时使用同轮 UI Brief 的对象显示尺寸与初始接触关系完成代入；`gamelogic Brief` 记录脚本需要的派生距离或判定窗口、可复核的参数关系和代入结果，并将安全裕量明确为“可用能力减成功所需能力”或“最窄有效判定交集”，结果为正后再确定默认值。静态坐标与显示尺寸仍由 UI Brief 维护；裕量覆盖帧步进、碰撞判定及动态目标在有效窗口内的位移。
- 玩家只能选择触发时机且动作后不可修正时，计算输入至判定的持续时间、双方相对位移和最窄有效输入窗口；每轮须在有限等待内出现至少一个可见、可命中的安全目标或推进通道，否则先约束随机范围、速度、方向、生成位置或判定区。
- 同一成功路径上的速度、间距、时间、尺寸和判定窗口作为一组参数确定；任一参数随进程变化时，同步更新受影响参数并保持正安全裕量。
- 连续移动或生成目标时，采用适合当前玩法的方向折返、等效滚动、对象回收补充或安全结束，使多轮成功后仍有清晰可达的下一目标。
- 推演若干次连续成功后的角色、目标和运动范围，在接近有效区域边界前更新方向、滚动或生成基准，并保持核心对象和完整运动轨迹可见。
- 目标生成、运动终点、命中判定和边界衔接共享同一坐标事实；方向变化后仍保留可达距离和判断窗口。
- 平台落地同时使用目标平台顶面、角色脚底接触点和水平可站立区。

## 局面与资源

仅在玩法涉及棋盘、组合、生产、资源、对象池或持续局面变化时应用：

- 每次有效操作原子更新内部状态、视觉反馈、文字数值和可选动作，再开放下一次输入。
- 随机、生成、池化或滚动具有上限、间距、复用、回收和无法继续时的恢复规则。
- 连续输入期间明确锁定、合并、排队或忽略，保持一次操作只消费一次。
- 无合法操作、资源断流、容量占满或目标不可达时，提供重排、补充、回收、稳定等待或安全结束。

## 结果与揭晓

仅在玩法实际包含选择、抽取、问答、评级、成功/失败或结果揭晓时应用：

- 每条有效输入和已定义异常路径映射到已定义结果；随机、同分、超时或输入不足仅在当前玩法明确包含对应条件时设置唯一仲裁或兜底。
- 一次流程只产生一个确定结果；结果锁定后继续输入保持当前结果。
- 结果文字、视觉、音频和内部结果事实一致，输入确认后及时进入计算、反馈和揭晓。

## 边界与重置

- 处理当前玩法真实可能发生的越界、碰撞、目标丢失、能力不可用、资源缺失和中断，并定义纠正、等待、降级、回收或安全结束路径。
- RecordEnd 停止输入、更新、生成器、timer、音频和检测，取消未完成过渡并保留最近已提交的稳定阶段。
- 下一次 RecordStart 使用统一 reset/restore 事实来源清理动态对象、缓存与临时反馈，并将所有被移动、缩放、换图、隐藏或动态创建的对象恢复到 Preview 基线。
