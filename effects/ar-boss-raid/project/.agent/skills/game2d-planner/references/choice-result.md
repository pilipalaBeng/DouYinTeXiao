# 选择结果创作规划

> 读取时机：Draft 确认后，主要期待是选择、抽取、翻牌、问答或有限输入后的结果内容时读取
> 职责边界：只补充选择结果的玩法 Brief，不定义素材、布局、API 或固定代码结构

## 适用判断

玩家的主要期待是完成一次选择、抽取或有限输入，并看到结果被确认、计算和揭晓时使用，例如塔罗、抽签、卡牌抽取、选项揭秘和简单结果问答。

## 核心循环

- 建立 `理解入口/选项 → 提交有效输入 → 输入确认 → 计算/抽取 → 悬念反馈 → 结果揭晓` 的完整因果链。
- 可见选择在意图、主题、风险或结果范围上具有真实差异。
- 每条有效输入和已定义异常路径到达已定义结果；随机、同分、超时、输入不足和索引异常仅在当前玩法明确包含对应条件时设置唯一仲裁或兜底。
- 一次流程只产生一个确定结果；结果锁定后继续输入保持当前结果和反馈状态。

## 结果内容

- 先区分输入入口与最终结果：按钮、类别或方向只负责直接确定结果，或选择一个结果池；不得自动将入口类别本身当作最终 `result_id`。
- 输入仅选择结果池且池内仍需随机抽取时，每个可达结果池必须包含至少 2 个不同结果；不得为每个入口只规划一个结果后仍描述为随机抽取。
- 每个最终结果具有稳定 `result_id`、标题、核心内容、必要解释、视觉主体和揭晓反馈；结果资源缺失只允许作为运行时异常降级，不得在规划阶段合并或省略结果。
- 结果文字、视觉、音频和内部结果 ID 共享同一事实；资源缺失时优先保持可读文字和流程完整。

## 揭晓体验

- 输入后立即确认已生效，再使用短促悬念、翻转、聚焦或阶段反馈完成揭晓。
- 结果主体成为视觉焦点，标题与简短内容清晰可读，并保留原玩法中仍有意义的元素。
- 只有实际需要时增加结果停留；普通结果、特殊结果、无效输入和降级结果使用可区分反馈。

## 边界与重置

- 多次点击、冲突选择、动画期间输入、抽取与超时同帧发生时给出唯一仲裁顺序。
- 无输入时保持当前可交互状态直到 RecordEnd；只有用户或已确认 Brief 明确规定无输入超时及其结果时，才进入对应中性结果或安全降级。结果资源缺失或能力不可用时进入预设等待或安全降级。
- RecordEnd 停止输入、timer 和音频，取消未完成过渡并保留已提交的结果阶段；下一次 RecordStart 再清空选择、结果 ID、文字、锁定和临时反馈，恢复结果主体、容器和 Preview。

## Brief 必需事实

- 输入入口、有效或无效输入、确认、计算或抽取、悬念、揭晓和停留流程。
- 有限结果集合、输入映射、随机或同分或超时仲裁、兜底和结果 ID 到文字、视觉、音频的唯一映射。
- 重复输入锁定、资源降级、结果层级与 reset。
