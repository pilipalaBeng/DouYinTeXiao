# 持续过程创作规划

> 读取时机：Draft 确认后，主要乐趣是棋盘、组合、合成、生产、经营、消除、排序或持续局面变化时读取
> 职责边界：只补充持续过程的玩法 Brief，不定义素材、布局、API 或固定代码结构

## 适用判断

玩家主要时间用于观察当前局面，反复选择对象或位置，并让局面、资源、组合或目标持续演进时使用。

## 核心循环

- 建立 `观察局面 → 选择合法操作 → 原子更新对象/资源/进度 → 反馈 → 新的合法选择` 的重复循环。
- 第一次有效操作清晰展示一个核心规则；后续操作复用该规则并逐步增加组合、目标或选择价值。
- 每次操作改变局面、资源、组合、进度、风险或可选目标，并在反馈结束后再开放下一次输入。

## 局面演进

- 从对象组合、空间容量、资源供需、目标需求、生产节奏、可选路径、限制条件或反馈强度中选择少量维度变化。
- 不同合法选择在后续局面、资源、进度或风险上产生可辨识差异。
- 在短体验内形成至少一次明确的小完成，例如清除目标、完成组合、升级、订单达成、解锁新操作或局面明显推进。
- 随机补充或生成先保证当前局面可继续，再增加变化。

## 可持续推进

- 初始局面合法且可推进；每次更新后保留至少一个可执行的下一步。
- 随机、生成、池化、生产和滚动具有数量上限、间距、容量、复用、回收和补充规则。
- 无合法操作、资源断流、容量占满、对象上限或目标不可达时，执行重排、补充、回收、提示、稳定等待或安全结束。
- 当前对象状态、视觉、文字数值、资源和产出在同一原子步骤中保持一致。

## 输入与反馈

- 有效目标、无效目标、连续点击、拖拽冲突、翻牌或动画期间输入和多个操作同时命中具有明确的锁定、合并、排队或忽略规则。
- 反馈说明发生了什么、局面如何变化、下一步可以做什么。
- 普通操作、关键组合、阶段完成、无效操作和死锁恢复具有不同强度的反馈。

## 重置

- RecordEnd 停止生产、生成、timer、音频和输入，取消未完成过渡并保留最近已提交的稳定阶段。
- 下一次 RecordStart 使用统一 reset/restore 事实来源清理动态对象、选择缓存、资源或局面数据与临时反馈，并将被移动、换图、缩放或隐藏的静态对象恢复到 Preview。

## Brief 必需事实

- 初始局面、核心操作、合法目标、操作结果、完成条件和下一合法操作。
- 局面或资源如何变化，不同选择如何产生差异，以及何时出现明确的小完成。
- 随机、生产、容量边界、死锁恢复、输入仲裁、反馈和 reset。
