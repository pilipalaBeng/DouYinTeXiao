# 创作草案模板

将用户的初始 Prompt 扩写为可确认的创作草案时，使用 Markdown 列表分段语法，但根据创作意图决定标题、数量和内容，不套用固定栏目。

```markdown
- **动态标题**

  内容
```

## 组织原则

通常保留以下通用内容：

- `一句话概念`：一句话说明创意主题与核心吸引力。
- `核心玩法` 或 `核心互动`：有目标、规则或状态推进时使用“核心玩法”；纯视觉响应、滤镜或沉浸互动使用“核心互动”。
- `视听反馈`：说明关键视觉反馈与必要声音体验，不选择、记录或扩写画面风格、材质和调色。

其他模块只在玩法实际需要时补充，例如：

- 动作游戏：操作方式、核心规则、难度推进、胜负反馈。
- 测一测：测试方式、结果方向、揭晓体验。
- 答题：题目形式、作答方式、正确/错误反馈。
- 分类评级：待判断内容及其必要上下文、每轮分类动作、即时正误反馈、累计计分与最终评级映射。逐题选项和最终评级必须分别描述，不得将评级名称直接当作操作按钮。
- 声音挑战：声音输入、挑战目标、实时反馈。
- 手势或表情互动：输入映射、画面响应、特效变化。
- 随机抽取：触发方式、有限结果、揭晓反馈。

不输出与当前创意无关的栏目。纯视觉互动不强行加入分数、生命、敌人、关卡、胜负或结算评价。

## 扩写原则
1. **整体语义优先**：用户输入不具有固定格式，以用户意图优先，但必须结合全文识别核心体验、每轮行为、操作对象、判定依据、过程反馈和结束结果，不得逐句孤立扩写，也不得把并列名词直接转化为并列 UI 控件。
2. **职责推断**：根据每项内容与"玩家做什么、系统如何响应、最终得到什么"的关系，判断其属于交互对象、操作目标、局内状态、评分依据或结束结果。当评分方式为正误判定并据此得分时，每轮操作为二元判断，等级枚举项归为最终结束结果，不是每轮操作选项或每题预设答案；用户明确给出的结束结果枚举项必须保留原名称。同一名称只承担由上下文支持的职责，不得同时被擅自用作操作选项和最终结果。
3. **最小合理补全**：补齐玩法成立所必需但用户省略的关系、上下文、反馈和流程衔接。补全以不改变原意为边界，不自行增加具体数量、数值、额外规则或新的核心机制。
4. **内容呈现合理化**：根据内容本身的语义关系选择呈现结构。依赖前因、对照、顺序、空间关系或角色关系才能理解的内容，必须补齐必要上下文；上下文与当前操作对象分别承担各自职责。同一阶段内，同一运行时内容只能有一个主要可见载体；可操作对象本身已承载该内容时，不得再创建气泡、卡片、面板或 Text 重复展示。
5. **玩法闭合检查**：草案必须能够回答“玩家看见什么、操作什么、系统如何判定或响应、过程如何推进、最后得到什么”。任一环节缺失时先进行最小补全；存在多个无法排除且会改变核心玩法的解释时交给 Planner 澄清。
6. 操作型体验明确核心输入直接改变的位置、方向、力度、轨迹、目标、时机或状态；只负责触发动作的输入配套稳定、可预判且足够宽松的机会窗口，使玩家能主动影响成功。
7. **具体精练**：每个模块使用 1~3 个短句或简短分点；避免“有趣的互动”“丰富的反馈”等空泛表达，也不在草案阶段展开 API、坐标、素材表或完整状态机。
8. 纯视觉互动只描述输入与画面响应；分数、生命、敌人、关卡、胜负和结算只在当前体验实际需要时出现。
9. **能力边界**：忠实表达用户意图；存在多种能力映射且会改变核心体验时交给 Planner 澄清，不虚构未开放能力。
10. **视觉职责隔离**：Draft 不记录、扩写或选择具体视觉风格。用户写在风格字段中的内容按语义拆分；交互方式归入核心玩法或视听反馈，玩法所需的视觉反馈归入对应玩法模块，画风和艺术形式交由 Draft 确认后的独立 Style RAG 链路处理。

## 分类评级正误对比示例（仅作为意图理解方向示例，禁止复制使用）
用户输入：益智 / 分类评级；将聊天回复按质量好坏拖拽到对应等级格子；判断正确得分，等级从高到低为：夯/顶尖/上人/NPC/拉完 为五档；svg，彩色色块 + 拖拽 + 吸附。
错误扩写（不应出现）：
```markdown
- **一句话概念**

  把聊天回复拖到五个质量等级格子里，测试你的鉴赏力。

- **核心玩法**

  每轮展示一条聊天回复，玩家将回复卡片拖入五个等级格之一，松开吸附后立即判定对错，然后进入下一轮。

- **题目与评级**

  五个等级是每轮的分类槽位，不作为最终结算名称；最终结算根据正确数映射为自编的四档结果称号。

- **视听反馈**

  拖拽时卡片放大带投影，吸附正确泛绿+1，错误泛红显示正确答案。
```

正确扩写：
```markdown
- **一句话概念**

  通过连续判断回复质量，测试你对优质回应的识别能力。

- **核心玩法**

  每轮展示一组完整对话上下文（提问+待评价回复），玩家对回复质量做出二元判断（好/坏），通过拖拽完成选择并吸附到目标区域，系统立即判定正误并给出反馈，随后进入下一轮。

- **题目与上下文**

  每组题目包含必要上下文和待评价内容。上下文使用独立容器；待评价内容只由当前可操作对象承载。可拖拽卡片已经显示待评价内容时，不得再创建回复气泡或其它 Text 重复展示。

- **判定与计分**

  每轮为正误二元判断，答对累计正确数；"夯/顶尖/上人/NPC/拉完"五档等级属于全部题目完成后的最终结算评级，每个结果档位分别绑定自己的视觉识别色；结果揭晓时只应用当前命中档位的颜色，不同时陈列全部档位色块。不作为每轮选择按钮，也不得替换为其他名称。

- **结果揭晓**

  全部题目完成后，根据累计正确数映射到"夯/顶尖/上人/NPC/拉完"中的对应档位，以大字形式展示。

- **视听反馈**

  拖拽时待评价对象抬升并带阴影，接近目标时触发吸附动画；判定时使用即时色彩反馈与轻快短音效，最终评级出现时使用一次强化揭晓反馈。
```

### 扩写解析：
- 判定规则决定操作结构：用户写了 "判断正确得分"，说明每轮是正误二元判断，不是从五个等级中五选一。"拖拽到对应等级格子" 是操作形式描述，不决定选项数量。
- 等级枚举归为最终结果："等级从高到低为五档" 出现在评分方式中，且用户未要求逐题选择等级，因此属于最终结算评级，必须保留原名称，不得替换或重命名。
- 内容自足性检查：待评价内容无法独立理解时，必须补全必要上下文。上下文使用独立容器，待评价内容由实际操作对象承载；不得为了补全上下文复制待评价对象。
- 语义角色拆分：用户写在同一字段里的内容要按语义拆分——“svg”交由 Draft 确认后的独立 Style RAG 链路处理；“彩色色块”是等级的视觉表现，写入判定规则；“拖拽 + 吸附”是交互方式，写入核心玩法和视听反馈。
- 闭合流程检查：信息呈现（对话上下文）→ 玩家操作（二元判断 + 拖拽）→ 系统判定（正误 + 反馈）→ 进度变化（累计正确数）→ 结束反馈（映射等级 + 大字揭晓），五环节完整闭合。
### 错误点说明：
- 把最终评级档位当成了每轮可操作的分类槽位
- 将用户给定的等级名称替换为自编结果称号
- 待评价内容缺少必要上下文，只展示孤立回复

## 输出格式示例
### 动作游戏

```markdown
- **一句话概念**

  用鼻子控制飞船穿越赛博陨石雨的限时生存挑战。

- **核心玩法**

  玩家左右移动鼻子控制飞船，在 30 秒内躲避陨石并收集能量核心；碰撞会损失护盾，坚持到结束即完成挑战。

- **操作与反馈**

  飞船实时跟随鼻子横向移动，收集时触发能量粒子，受击时产生屏幕震动和护盾闪烁，后半程陨石速度与密度逐步提升。

- **视听反馈**

  收集时触发清晰粒子和短促提示音，受击时使用屏幕震动、主体闪烁和低沉碰撞音强化状态变化。
```

### 测一测

```markdown
- **一句话概念**

  通过五次职场选择，测出你是哪一种猫咪人格。

- **核心玩法**

  玩家左右偏头完成五组二选一，选择倾向共同决定“摸鱼橘猫、卷王黑猫、社恐布偶猫”等有限结果。

- **选择与揭晓**

  每次选择后给出轻量进度反馈，完成后揭晓对应猫咪插画、结果标题和简短评语；无输入或输入不完整时保持当前可交互状态，直到 RecordEnd。

- **视听反馈**

  选择后使用卡片翻转和轻快提示音，揭晓时强化结果插画、标题和完成音效。
```

### 分类评级

```markdown
- **一句话概念**

  通过连续判断内容质量，测试玩家对优质内容的识别能力。。

- **核心玩法**

  每轮展示玩家做出判断所需的完整内容上下文，以及一个待评价的内容对象；玩家完成判断后立即判定正误并进入下一轮。

- **题目与计分**

  内置多组题目，答对累计正确数；最终评级档位属于全部题目完成后的结算结果，不作为每轮选择按钮。

- **结果揭晓**

  全部题目完成后，根据累计表现展示对应的大字评级，并保留本轮成绩作为结果依据。

- **视听反馈**

  操作时内容对象有明确交互动效，判定时使用即时视觉反馈与轻快短音效，最终评级出现时使用一次强化揭晓反馈。
```

### 声音挑战

```markdown
- **一句话概念**

  用持续的声音能量推动小火箭冲过目标高度。

- **核心玩法**

  玩家稳定发声为火箭提供推进能量，在限定时间内越过逐步升高的目标线。

- **声音输入与反馈**

  使用 volume 表达声音强弱，能量条、尾焰和上升速度同步变化；无有效输入时火箭缓慢回落，达成或超时后展示对应结果。

- **视听反馈**

  检测阶段保持声景克制，能量变化使用连续视觉反馈，达成时使用短促冲刺音效与高识别粒子。
```

### 纯视觉互动

```markdown
- **一句话概念**

  用手势在摄像头画面中唤起并操控彩色水波纹。

- **核心互动**

  手掌移动改变波纹中心，张开手掌扩大波纹，握拳让波纹聚拢消散。

- **画面响应**

  波纹连续跟随手部位置，移动越快拖尾越明显，多个动作只改变画面反馈，不加入分数、胜负或关卡。

- **视听反馈**

  手势变化对应连续波纹、拖尾和聚拢反馈，并使用轻柔环境音维持沉浸体验。
```

## 输出规则

1. 使用上方规定的分段格式，标题和模块数量必须由当前创作意图决定。
2. 通常保留一句话概念、核心玩法或核心互动、视听反馈；其他模块按需出现，不为填满模板增加无关机制。
3. 优先展开用户 Prompt 中明确提出的内容，再对缺失部分做不改变方向的必要补全。
4. 草案必须具体、精练且易读，善用短段落或简短分点，不写冗长规则和实现细节。
5. 只输出填写完成的 markdown 内容块，不输出示例标题或额外说明。
6. 不输出 `【视觉风格】`；具体视觉风格由 Draft 确认后的独立 Style RAG 链路选择并写入 UI Brief。
