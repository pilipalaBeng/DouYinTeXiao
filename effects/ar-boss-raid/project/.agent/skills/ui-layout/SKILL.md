# 通用 UI 规范

本 Skill 只定义跨品类复用的 UI 契约。固定画布、安全区、HUD 尺寸、玩法布局和引擎实现由当前品类或执行阶段的 Skill 补充。
品类 Reference 可收紧通用规则；两者冲突时，以当前品类 Reference 为准。

## Reference 路由

- 2D/AR 游戏 UI：读取 `.agent/skills/ui-layout/references/game-ui-layout.md`；Planner 生成游戏 Brief 时还必须读取 `.agent/skills/ui-layout/references/fixed-layout-reference.md`，将固定布局图的区域职责和坐标写入 UI Brief。
- 非游戏视觉特效 UI：仅在用户明确需要控制、输入提示、检测状态或效果信息 UI 时读取 `.agent/skills/ui-layout/references/visual-effect-ui-layout.md`。
- 同一任务同时包含游戏和视觉特效时，只加载与当前阶段直接相关的 Reference；不要为可能的后续需求预读另一份。

## UI 容器

- UI 图片内部禁止生成可读文字、数字、字母、logo、水印、伪文字或文字占位内容；文案使用独立 Text 对象。
- 按钮、面板、信息栏、卡片、标签等功能性容器必须具有明确的文字承载区、交互边界和可辨识轮廓；透明度、材质和填充方式由当前品类 Reference 决定。
- 容器默认采用一个基础形状和一层连续实体填充；描边是否存在及其样式由当前品类和全局风格决定。没有功能价值时不增加内轨、双重边框、嵌套页签、重复胶囊、状态灯、分割条或密集角花。
- UI 层级依靠单层描边、轻微阴影或明确明度差建立，不依靠背景模糊、堆叠装饰或未经品类 Reference 允许的透明效果制造复杂度。
- 常驻、状态类、可交互或结构性文字必须由所属容器承载。短暂提示、操作反馈和装饰性大标题可以独立显示，但必须保持高对比和清晰边界。

## 文字容量

- 容器必须按最长预期运行时文案规划，记录字号、单行或多行、最大行数、内边距、图标占用、图文间距、文字安全区和图标安全区。
- 图标与文字使用互不重叠的安全区；图标区域不计入文字可用宽度。
- 文字安全区必须避开描边、圆角、斜切角、图标、装饰和功能性强调区域，不得直接使用 PNG 完整外接矩形。
- 单行文字容器水平内边距不得小于 `16px`、垂直内边距不得小于 `10px`；按钮左右内边距不得小于 `20px`、上下内边距不得小于 `10px`；多行提示框、结果卡和说明卡水平内边距不得小于 `24px`、上下内边距不得小于 `20px`；图标与文字间距不得小于 `12px`。
- 容器最小宽度 = 左内边距 + 图标宽度（若有）+ 图文间距（若有）+ 最长文字宽度 + 右内边距。先确定 Text 最终可用宽度，再按最长文案与换行模式得到最大行数 `N`；文字块高度 = `fontSize + (N - 1) × fontSize × (1 + lineSpacing)`，容器最小高度 = 上内边距 + 文字块高度 + 下内边距。单行取 `N=1`；多状态容器按最长、最宽的状态文案规划。
- 仅承载文字的题目框、提示框、选项卡和标签框，最终高度必须贴合上述容器最小高度。除描边、圆角或风格轮廓确需的结构余量外，不得额外留出大块上下留白；结构余量每侧不得超过 `8px`，因此最终高度不得超过 `上内边距 + 文字块高度 + 下内边距 + 16px`，禁止出现容器高度为文字块高度 `4~10` 倍的比例。
- 含结果角色、插画、图标或其它真实内容槽位的复合容器，按完整内容组总高度计算高度，不把非文字槽位误判为空白；绿色常驻交互区对象继续执行所属品类的既有位置、完整落区和高度限制，本条不得用于移动或扩大绿色区对象。
- 尺寸不足时先检查容器是否锁定：未锁定容器可在所属区域内扩大，但不得制造新冲突；锁定容器不得扩大、移动、缩小字号或减少内边距，只能缩短文案、合规换行或使用已规划的备用文案，仍无法容纳时报告容量冲突。
- 以下文字对齐规则均为默认值，品类 Reference 有更具体规则时从其规则；所有文字必须显式指定水平和垂直对齐：按钮和短标题居中；图标右侧标签左对齐且垂直居中；多行正文左对齐且顶部对齐。
- 每个 Text 必须显式选择 `boxDimension`：独立无底板短标签使用 `dynamic`，限宽多行正文使用 `fixedWidth`；绑定按钮、标题栏、HUD、标签或其它容器且要求居中的 Text 必须使用 `fixedSize`。
- “水平、垂直居中”必须落实为可计算矩形：Text 最终矩形等于所属 `textSafeRect`，Text 中心等于 `textSafeRect` 中心，并同时设置 `horizontalAlignment=center`、`verticalAlignment=center`。不得只写“居中”却保留任意 `x/y` 或使用 `dynamic`；按用途选择 `autoLineBreak`、`cutOff` 或 `clamp`。文本框自适应只改变 Text 外框，不得自动缩小字号；运行时文案按最长预期内容预留容量。
- 容器存在非对称装饰时，以实际 `textSafeRect` 的视觉中心为准，不以 PNG 完整外接矩形中心代替。
- 两至三行的短提示作为一个文本块在文字安全区内水平、垂直居中并使用统一正值行距；阅读型正文保持左对齐、顶部对齐并使用正值行距。
- 数值型信息栏文字可居中或右对齐，但同一组必须使用一致的对齐方式。
- 容器内没有图标或其它内容占位时，文字在文字安全区内水平、垂直居中。
- 不得使用空格、全角空格或手工换行模拟对齐；同行模块按容器外框对齐，不只比较文字中心。

## 可读性

- 文字必须与实际显示背景保持清晰对比；浅色背景使用深色文字，深色背景使用白色或高明度文字。
- 渐变、纹理、动态或不可预测背景上的文字必须使用清晰描边、投影或实体不透明容器。
- 独立短文字优先使用清晰描边或轻微投影；发光只用于当前品类和风格明确允许的场景，且不得削弱字形。
- 正文、数字、符号和辅助文字都必须保持清晰边缘和可辨识字形，不得只保证标题可读。
- 独立短文字必须定义明确的 Text 矩形，并在矩形内按规划对齐，不得依靠默认尺寸或视觉目测定位。
- 小尺寸文字必须通过容器、明确对比或描边保持可读，不得依赖自动缩放。

## 图文组合

- 只有图片本身是按钮、卡片、标签、信息栏或结果面板等真实文字容器时，Text 才能与图片组合。
- Text 与容器组合时使用容器对象 ID 建立 `textContainerId` 关系；先根据容器外接矩形和内部安全区计算 Text，再将最终画布矩形写入执行计划。容器位置调整时重新计算绑定文字的最终矩形。
- 含图标的容器必须分别定义 `textSafeRect` 与 `iconSafeRect`；图标在左侧时，文字从图标安全区右侧开始。
- 图标位于文字上方时，文字必须使用独立的下方安全区，不得覆盖图标。
- 包含多个子对象的容器必须为每个子对象提供互不冲突的内部安全矩形。
- 单标签 Text 只有在 `textSafeRect` 明确等于容器内部完整可用区域时才能与容器共享中心点，且不得覆盖描边、圆角、图标或装饰。
- 若容器不能同时容纳图标、间距、文字和内边距，统一按“文字容量”的锁定状态处理：只扩大未锁定容器；锁定容器改用合规换行、缩短文案或已规划备用文案，仍无法容纳时报告冲突。
- 容器底板内含图像、图标和文字时，先将它们视为一个完整内容组，在容器可用内容区内按规划整体对齐；文字在各自安全区内排版，不得脱离图像单独按容器几何中心定位。独立边缘装饰可锚定容器边缘，但不得遮挡文字安全区、点击区域或主要图像识别区域。
- 内容组总高度按各图像和文字块的实际高度、图文间距与字段间距累加；内容组起点 = 容器内容区顶部 +（容器可用内容区高度 - 内容组总高度）/ 2。各段从上一段底部继续排列，不得逐行写死屏幕 `y` 坐标或让多个字段重叠。
- 同一复合内容组内部允许按明确层级叠放，但必须记录前后关系、语义归属、点击区域以及允许和禁止遮挡的部分；关键文字安全区、点击区域和主要图像识别区域始终不可被遮挡。
- 判断重叠冲突时，不只检查外接矩形是否相交，还必须检查是否属于同一复合内容组、是否破坏阅读顺序或语义归属、是否混淆点击区域、是否颠倒视觉主次或遮挡主体识别区域。只有独立模块之间的非预期相交才判定为冲突。
- 移动未锁定复合内容组时应整体移动；存在锁定子对象时，锁定对象保持不动，只调整未锁定子对象，不得为消除冲突临时改变组合关系。
- 绑定容器的 Text 不得因容器锁定而沿用错误坐标。容器移动、缩放或最终素材比例变化后，必须重新由 `textSafeRect` 推导 Text 的 `x/y/width/height`。

## 生命周期与间距

- 只在特定阶段有用的 UI 必须规划显示和隐藏时机，不得默认永久可见。
- 进入新的 UI 阶段时，隐藏上一阶段不再使用的输入、按钮和临时说明。
- 同阶段可见的重要 UI 模块和文字矩形之间必须保留可辨识间距；精确数值由当前品类 Reference 定义。
- 空间不足时只调整未锁定对象，依次缩小非核心元素、调整布局、阶段性隐藏次级元素或更换区域，不得通过重叠、降低透明度或压缩必要间距解决。
