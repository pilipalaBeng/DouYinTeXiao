# 视觉特效 UI 与布局规范

本 Reference 由 `ui-layout` 在非游戏视觉特效明确需要用户可见 UI 时加载。纯渲染、纯材质或用户未要求 UI 的效果不加载本文件，也不主动增加控制面板、参数展示或状态提示。

## 适用范围

- 用户明确要求的效果开关、模式选择或运行时参数控制。
- 用户需要理解输入方式时的手势、关键点或相机输入提示。
- 用户明确要求展示的检测状态、数值或效果反馈。

## 布局边界

- `Assets/design_brief.md` 中的作用对象、作用范围、边缘质量、遮挡关系和“明确不改变”区域是布局事实源；UI 不得遮挡这些区域或改变效果验收条件。
- 屏幕空间、相机输出和全屏效果以效果画面为视觉主体。用户要求 UI 时，优先使用不遮挡目标区域的最小必要容器，不增加大面积背景 PNG、装饰框或与效果无关的常驻面板。
- 面部、身体、手部、宠物或其它语义检测驱动的效果，UI 必须避开对应语义目标和关键点区域。面部检测场景还应遵循已选 Vision 能力中的人脸避让规则。
- 若无法同时满足用户要求的 UI 与效果可见范围，必须在 brief 中明确布局冲突并调整 UI，而不是缩小、裁切或遮挡核心效果。
- 用户明确要求半透明或玻璃控制面板时，可以使用 `sceneOps Image.alpha` 创建单一、均匀填充的半透明表面；不得用透明度伪造局部孔洞、空心边框或镂空内部。

## 内容与状态

- UI 只展示用户可理解的效果语义和用户明确要求的信息，不展示 RenderTexture、Pass、材质属性名、资源 GUID、组件 GUID 或内部节点。
- 手势、关键点或检测提示不得虚构能力未提供的置信度、状态或字段；可展示内容以已选 Vision/API 契约为准。
- 临时输入提示、检测状态和控制 UI 必须在 `design_brief.md` 中记录触发条件、显示内容、显示时机和隐藏时机；执行阶段不得自行改为永久可见。
- 运行时参数 UI 只在用户明确要求可见控制时规划。材质 `UIPROPERTY` 或脚本序列化字段只是工程可编辑接口，不自动等价为用户画面中的 UI。
