# 固定布局参考图合同

本文是固定布局参考图的文字释义。Planner 在 Draft 确认后生成 `Assets/design_brief_ui.md` 时，将图片与本文共同作为布局事实源；图片表达区域关系，本文提供精确坐标和落盘要求。颜色只表示区域职责，不是最终画面或资产配色。

## 画布与区域

### 通用分区
- 画布固定为 `720×1280`，原点位于左上角，Y 轴向下。
- 主安全矩形为 `left=40、top=148、width=640、height=947`，覆盖 `x:40~680、y:148~1095`。
- **蓝色主内容区**：`left=40、top=148、width=640、height=773`，覆盖 `x:40~680、y:148~921`。承载顶部信息、核心玩法主体、玩法空间、结果主体、必要说明、临时提示和相关反馈。
- **顶部信息起点**：非测试型游戏需要 HUD 时，在蓝色主内容区顶部放置一个 `left=40、top=148、width=640、height≤122` 的完整横向 `hud_bar`；测试型游戏禁止 `hud_bar`，最多放置一个从 `top=148` 起排的无底板大标题，必要题目或上下文紧接其后。
- **绿色常驻交互区**：`left=40、top=921、width=640、height=174`，覆盖 `x:40~680、y:921~1095`。承载玩法确实需要的 tab、button、短标签、横向短卡片，以及手指拖拽玩法中的短标签分类区、目标槽和投放区。手部交互对象先组成完整横向组。组内每个成员的视觉主体、文字、描边、阴影和点击或拖入判定范围均不得相交，相邻成员完整外接矩形净间距不得小于 `16px`。全部成员必须完整位于该区域；使用内部安全范围 `x:48~672、y:929~1087` 时，完整高度不得超过 `158px`。
- **红色非重要交互区域**：蓝色主内容区与绿色常驻交互区之外的画布区域，包括顶部 `y:0~148`、左右各 `40px` 边距和底部 `y:1095~1280`。只允许非重要、非文字承载、非主要交互的边缘玩法元素或轻量装饰进入；重要按钮、HUD、常驻卡片、结果面板、玩法网格和可读文字不得进入。
- 区域边界归蓝色主内容区和绿色常驻交互区；红色区域不与主区域共享边界像素。

### 测一测输入阶段专用合并分区
以下分区仅在命中 `quiz-result` 且处于输入阶段时启用，不影响其它游戏类型和结果揭示阶段。
- **测一测内容区**：直接使用蓝色主内容区 `x:40~680、y:148~921`，不得在 `y=270` 重新起排。
- **顶部内容流**：无底板测试标题完整外接矩形固定为 `top=148`；必要题目或上下文按精确文字高度和 `16px` 净间距紧接标题排列。
- **人脸优先可视区**：`left=201、top=266、width=315、height=438`，覆盖 `x:201~516、y:266~704`。实体 UI、可读 Text、卡片和非脸控玩法对象优先避让该区域；内容容量或交互关系要求连续布局时允许局部进入，但不得大面积持续遮挡人脸主体或同时遮挡主要五官。
- **左右可用区**：`x:40~201、y:266~704` 与 `x:516~680、y:266~704`。
- **下方可用区**：`x:40~680、y:704~921`。手指拖拽对象和靠近底部目标的操作主体优先放置于此。
- **绿色常驻交互区**：继续使用 `x:40~680、y:921~1095`，不并入测一测内容区。
- 脸控玩法必需的空心检测框、关键点或轻量反馈可以进入人脸优先可视区；结果揭示阶段不执行该避让规则。

## 落区规则

- 所有元素按包含面板、描边、阴影、文字、图标和装饰的完整外接矩形判断，不得仅按中心点判断。
- 本文区域使用 `left/top/width/height` 描述外接矩形；`Scene Layout Plan` 和 `sceneOps` 的 `absolute x/y` 表示对象最终外接矩形中心点。矩形换算为场景坐标时统一使用 `x=left+width/2`、`y=top+height/2`。
- HUD 的外框固定使用 `left=40、top=148、width=640、height≤122`；不得拆成多个分散面板。
- 核心玩法主体和玩法空间优先放在蓝色主内容区。只有非重要、非信息承载的异形轮廓或动态边缘元素可以自然延伸进红色区域。
- 绿色区域禁止大面积 UI 框、竖向长面板、`2:3` 竖卡、`1:1` 大卡片和多行说明面板。元素放不下时缩短高度、等比缩小或减少非必要内容，不得向上侵入蓝色主内容区。
- 无常驻按钮时，绿色区域保持 AR 透传留白；核心玩法确需更大纵向空间时可进入绿色区域，但不得因此把绿色区域中的交互元素上移到蓝色主内容区。
- 结构性 UI 不得完全覆盖或大面积遮挡核心主体的识别区域。空间不足时优先缩减非必要文字和辅助 UI，不得优先压缩核心主体。
- 参考图中的人物、平台、尖刺、文字和颜色蒙层只是区域示例，不属于任何游戏的待生成内容，不得复制到 Brief 或设定图。

## Brief 落盘

- `Visual Assets (PNG)` 只定义素材身份、用途、生成尺寸、构图和生成约束，不新增位置列。
- 所有静态区域归属、坐标、尺寸、容器、文字容量、对齐、间距和禁止重叠关系写入 UI Brief 的 `Scene Layout Plan`。
- `Scene Layout Plan` 中每个 `scene_static` 和 `offscreen_template` 对象都使用可执行的 `Position Mode` 与数值位置；固定 HUD 使用 `pinned` 并逐字记录 `left=40、top=148、width=640、height≤122`，其它 `absolute` 对象记录中心点 `x/y` 和最终 `width/height`，不得只写“居中”“偏上”“靠下”等模糊方位。
- 设定图构图只包含 UI Brief 已确定的代表性状态可见对象：首屏状态以 gamelogic Brief 中 `Initial Visibility=true` 为准，游戏中或结果揭示状态逐字引用对应状态 ID 与事件名。其它阶段对象仍在 `Scene Layout Plan` 中记录最终安全位置，但不混入当前代表性状态设定图。
- 运行时显示、隐藏和状态切换继续只写入 gamelogic Brief 的 `Runtime Visibility Plan`，不得在本合同或 UI Brief 中建立第二套生命周期事实。
