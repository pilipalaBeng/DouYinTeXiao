## 〇、开工前必须先钉死的三条规格裁定（我发现的上游口径冲突，已裁决）

这三条如果不先钉，后面所有资产尺寸都会返工。请团队以本裁定的口径为准。

**裁定 1 —— 导出倍数与屏幕显示尺寸的精确关系（上游表述不严谨，此处给可执行版）**
- 上游写「导出 ×8 → 512，96/128 基准 ×4 到 512」。实测：`128×4 = 512`✅、`64×8 = 512`✅，但 `96×4 = 384 ≠ 512`、`96×5.33 = 512`（非整数）。**96 基准无法整数倍落到 512。**
- **裁定**：导出尺寸 = 逻辑尺寸 × N，N 为整数，**导出长边 ≤ 512**（这是硬上限，不是「必须等于 512」）。
  - 2 的幂逻辑尺寸（16/32/64/128）→ 导出正好 512；
  - 非 2 的幂逻辑尺寸（24/48/96/160）→ 取「不超过 512 的最大整数倍」（如 96→480、24→480、160→480）。
- **屏幕显示尺寸裁定**：`显示尺寸 = 导出尺寸 × (1 / 2^n)`（n 为非负整数，即 1/1、1/2、1/4、1/8…）。
  理由：导出图内部是「逻辑像素 × N」的实心色块；只要按 2 的整数次幂**下采样**，落在每个逻辑块内的采样点颜色一致，屏幕像素块**严格均匀**，无半像素、无糊边。**禁止任意百分比缩放**（如 70%、150%）。
- 每条资产在「四、规格总表」里都给了 (逻辑 / N / 导出 / 1:2^n / 显示)，照表执行即可。

**裁定 2 —— Boss 画布选 128×128（不是 96×96）**
- 理由：① 128 是 2 的幂，导出正好 ×4 = 512，全程无余数；② Boss 是全场视觉主体，需要在同一张图内同时容纳「独眼 + 双小角 + 圆滚身体 + 两条小腿 + 头顶出战牌挂点」，96 画布会把这五件元素挤成糊团，剪影辨识度不达标；③ 96 只能导出 480，白白浪费 32px 且引入非 2 幂关系。
- **结论：Boss 本体逻辑画布 128×128。**

**裁定 3 —— 字体策略（结论先行）**
- **拉丁字母 / 数字 / 评级字母（S A B C）→ 自制像素字**（固定字符串直接烤成整词图；数字用 0–9 图集）。理由：这些字高频出现且是「像素街机味」的主要来源（伤害数字是全项目视觉权重最高的元素），必须像素级可控。
- **中文（教学提示、按钮中文、状态页文案、调侃文案）→ 系统字体 2D Text**。理由：一人团队自造中文字模不现实（需数千字模），系统字体零资产、零包体。
- 若工期极紧，**可整包降级为「全部系统字体」**（则字体资产归零）；但伤害数字会失去像素味，不推荐。

## 一、风格定义

### 1.1 风格定位

**「像素街机厅 · 荧光 CRT」**——80 年代街机厅 CRT 屏的荧光质感 + 现代 indie 像素的干净剪影。

一句话可执行描述：**暗底高对比、厚描边、大色块、暖冷对冲、拒绝一切柔和过渡。**

| 维度 | 规格（形容词 + 材质/光照/色彩） |
|---|---|
| 整体气质 | 复古街机、硬朗、高对比、略带「屏幕发光」的电子味；不软、不萌、不写实 |
| 造型语言 | 圆钝厚重的**大色块**剪影；主体要素用 2–3 个色阶（亮面/暗面/内暗边）交代体积；**禁止渐变、禁止写实纹理** |
| 描边 | 全项目统一 **1 逻辑像素 `#140c1c` 外描边**；重要主体（Boss 本体、出战牌）**再叠 1 逻辑像素 `#442434` 内暗边** 制造厚度（详见 3.2） |
| 材质 | 石质/塑料/金属只有**三档平涂**（亮面/中间调/暗面），不做高光点、不做反射；金属靠 `#8595a1` 亮边 + `#4e4a4e` 暗部暗示 |
| 光照 | 统一**左上 45° 单光源**（左上亮、右下暗），全项目光照方向一致，保证「同一双手」观感 |
| 色彩 | DB16 16 色固定预算（见 1.2），暖（橙 `#d27d2c` / 黄 `#dad45e` / 红 `#d04648`）与冷（蓝 `#597dce` / 青 `#6dc2ca` / 深蓝 `#30346d`）对冲；底子偏暗（暗紫/深蓝/近黑）以托出摄像头实景上的可读性 |
| 抖动 | 需要 2 色之间过渡时只用**棋盘抖动 / 1px 横纹**，**禁止模糊与半透明羽化**（半透明只允许 alpha=0 或 255） |
| CRT 感落地范围 | **只在 UI 面板/状态页上叠 1px 横纹（`#deeed6` 12% → 用 `#8595a1` 单像素横线表达）**；**严禁整屏扫描线或蒙层覆盖摄像头**（AR 玩法红线） |

5. **血条刻度烤进底框**：刻度是静态的，直接画进 `hp_frame`，不单列资产。

## 三、逐资产规格

### 3.1 Boss-01「圆滚魔像」视觉规格

**造型描述（可照做）**
- 主体：一颗**圆钝的、略呈梨形的巨石躯干**，占画布约 88×76 逻辑像素，坐落在两条**粗短的方形小腿**（各约 20×18）上；躯干下部有 2–3 道**横向石缝**（`#442434` 1px 横线）交代「石头堆」质感。
- 独眼：**单只大圆眼**，位于躯干上 1/3 正中，直径约 28 逻辑像素，外圈 `#346524`、虹膜 `#dad45e`（常态）/`#d04648`（暴怒）、瞳孔 `#140c1c`、高光 2×2 `#deeed6`。
- 双小角：头顶左右各一，**指天小短角**，高约 14、基宽 10，基座 `#854c30`、尖端 `#d27d2c`。
- 头顶挂点：双角之间留 **24×24 逻辑像素** 的净空作为出战牌挂点区（见 3.3）。
- 手臂：两条**粗短石臂**贴近身体两侧（常态垂放 / 暴怒微抬 / 认输高举 / 假死摊平）。
- 憨中带凶：重心低、比例头大身圆、动作迟钝 → 危险但有喜感，天然「去暴力」。

**头像装入方式（预设选择器 = 本轮唯一路径；相册 = 远期能力）视觉规范**

> **本轮口径**：**预设 6 选 1 是必经前置**（进局前必选）。相册自选头像为**远期能力** —— 当前编辑器版本**不支持** `Image Picker`（实测报 `Unknown scene object config id`），**本轮不实现、也不作为兜底路径**。

1. **选择（本轮）**：玩家在开局选择器里从 6 个预设头像（`avatar_01 … avatar_06`）中选 1 → 记为本次挑战的出战头像。**未选时不引入专用占位资产**，而是**沿用选择器默认高亮的 `avatar_01`** —— 流程上不存在「未选中间态」。
2. **双网格投放（本轮）**：
   - **选择器内** → `avatar_XX_64`（逻辑 64 / 导出 ×8 = 512 / 显示 64×64 / **颗粒 1**，细节最足）。
   - **Boss 头顶出战牌孔径** → `avatar_XX_16`（逻辑 16 / 导出 ×32 = 512 / 显示 64×64 / **颗粒 4**，与相框同颗粒）。
   - 两者**各自原生绘制、互不缩放**：16 **不是** 64 缩小、64 **不是** 16 放大。同一人物在两处**并非逐像素相同**，而是**同一造型的两种分辨率**（保证两个观看距离下都清晰）。见 §4.1「双网格」。
3. **装框**：头像居中对齐 16×16 孔径，外框覆盖遮挡边缘 1–2 逻辑像素，形成「装裱」感。
4. **远期（相册路径，本轮未实现）**：接入时才生效的预置规范 —— 抠图 → **降采样到 16×16 逻辑网格** → 颜色**最近邻量化到 DB16**（含 1px `#140c1c` 描边）→ 装框；**兜底 = 保持玩家已选预设**（相册失败/取消 = 退回预设图，**不新增专用占位或锁形资产**）。
   > ⚠️ 该远期路径**不做任何资产预留**：不建 `*_placeholder` / `*_locked` / `*_fail` 类贴图。

**★ 关键：如何让「牌子」的视觉定性明确（不要像「朋友的脸变成了怪物」）**
这是本特效的合规命门，视觉侧用**四重手段**把语义钉死为「一块牌子」：
1. **怪物有自己的脸**：Boss 本体是**独眼石魔**，从头到尾保留它自己的眼；头像相框**不覆盖 Boss 的眼睛/头颅**，而是**举在头顶上方**。→ 观众一眼看到「怪物 + 它举着一块牌」，而不是「人脸长在怪物上」。
2. **可见的旗杆/支架**：相框底部**必须带 8 逻辑像素的实体旗杆**，把牌子与 Boss 头顶**物理性连起来且留出可见间隙**（不相贴）。旗杆是一根「东西」，读完即知是举牌。
3. **牌子自身的「物性」**：厚边框（≥4 逻辑像素）+ 四角铆钉/挂环 + 一条小旗尾/飘带；牌子可带 **±3° 内的小倾斜**（像素级用错位一格表达），像被举着的实物而非贴图。
4. **接触点明确**：牌底与 Boss 头顶之间**不共用描边**（各自独立 `#140c1c` 外描边），中间可见摄像头实景透出 → 视觉上「分离的两个物件」。
> 文案配合（交创意/UI）：「举着 TA 的应援牌的魔像」——视觉与文案同向，杜绝「换脸」联想。

### 3.3 枪与准星规格

**枪（第一人称近似视角）**
- 结论：**用「竖屏第一人称炮口」而非完整枪身**。理由：竖屏 + 摄像头实景里，完整枪身会侵占安全区、遮挡画面；一个从**屏幕右下伸入、炮口朝左上**的粗短像素炮管，既保留「我在开枪」的指向感，又最小化遮挡。参考形态 = 街机光枪的下半截。
- 规格：逻辑 **128×64**，导出 ×4 = **512×256**，显示 1/2 = **256×128**。
- 造型：炮管主体 `#757161` 金属 + `#8595a1` 左上高光 + `#4e4a4e` 右下暗部；枪口环 `#4e4a4e`；握把/护木若入画用 `#854c30` 木色；整体 1px `#140c1c` 描边。

- 朝向：静止时炮口朝左上指向屏幕中心；后坐力/换弹时**只做整数像素位移，不做自由旋转**（平台禁非 90° 整数倍旋转；如需倾斜用 2–3 帧预烤角度图，不给连续旋转）。**v2 枪不跟随手指**。
- **v2 位置不变**（枪为 2D 屏幕元素，与 AR 无关）；**准星**见下（改固定屏幕正中）。

**枪口闪光 muzzle_flash**

### 3.7 AR 锚定层（L2）世界尺寸口径（v2.1 新增）

**适用范围（只此一层）**：**AR 层 = L2** —— `boss_body_*`、`boss_eye_*`、`boss_shield*`、`boss_head_frame_a`、`avatar_XX_16`。
> **屏幕层（L3–L6：枪、准星、HUD、状态页、结算卡、选择器）不适用本节** —— 它们仍按 §3.4 口径 ①（屏幕像素 / 安全区），尺寸固定、与距离无关。

**1. 为什么本层不用"米"**
AR 相机对象 `TargetTrackingCameraJS` 的 `properties` 为**空** → **FOV 不可设、不可读、逐帧可变** → 无法把"米"换算成屏幕像素，**"米"在本引擎没有依据**。故本层改用**占屏幕比例（占屏比）** —— 这是唯一可校验的口径。判据出处：`tech-spec §2.8`（tech-architect 实测）。

**2. 尺寸口径：占屏比**
| 项 | 规格 |
|---|---|
| 基准锚点 | **Boss 初始投影 ≈128–192 逻辑像素**（引 `tech-spec §6-10`）—— 即 Boss 逻辑画布 128 在初始状态占屏约 **128 ~ 192 屏幕像素（≈ 1× ~ 1.5×）** |
| 基准观看距离 | **1.5 m** |
| 远近容差 | **0.8–3.0 m**，但**只作相对口径**：近端 Boss 更大、远端更小；**不承诺任何"米数 ↔ 像素值"换算**（不可换算） |
| 校验方式 | 实机取初始帧，量 Boss 投影的屏幕像素宽 → 落在 **128–192** 即通过 |

**3. 颗粒（关键，且是已知代价）**
- **AR 层的显示倍率由距离决定，不保证整数** → 会出现**非整数倍**（如 1.5× = 192/128），此时色块**不严格均匀**。
- **这是 AR 世界锚定的固有代价，属"已知技术债"，本轮不修**（登记见 §4 末「已知颗粒不一致（技术债）」）。
- **三条缓解（必须做到）**：
  1. **采样必须 Nearest**（`filterMin/Mag=Nearest`、`filterMipmap=None`、`enableMipmap=false`、`Max Resolution=Size512`）—— 任何倍率下**绝不线性插值**，宁可色块不均也不糊；
  2. **把基准观看距离 1.5m 调到最接近整数倍的档**（优选 **1×** = Boss 占屏 128 逻辑像素，即"屏幕像素 = 逻辑像素"），保证**默认最常用距离下最干净**；
  3. **不许为凑大小对 Boss 做非整数缩放**（如强乘 1.2 倍）—— 那会同时制造"距离"与"缩放"两个变量。
- **颗粒表述规范**：AR 层资产的颗粒一律写成「**基准观看距离 1.5m 下的等效颗粒**（+ 随距离变化趋势）」，**不写固定颗粒值**。

| AR 层资产 | 逻辑 | 导出 | 1.5m 基准占屏（逻辑像素） | 等效颗粒（1.5m） | 随距离变化 |
|---|---|---|---|---|---|
| boss_body_idle / enrage / faint / surrender | 128×128 | 512×512 | 128 ~ 192 | **1 ~ 1.5** | 拉近 ↑（更粗/更糊）、拉远 ↓ |
| boss_eye_* | 16×16 | 512×512 | 16 ~ 24 | **1 ~ 1.5** | 同上（**与本体同倍率，不得独立缩放**） |
| boss_shield / boss_shield_core | 64×64 / 8×8 | 512×512 | 64 ~ 96 / 8 ~ 12 | **1 ~ 1.5** | 同上 |
| boss_head_frame_a | 24×32 | 384×512 | 24 ~ 36（宽） | **1 ~ 1.5** | 同上 |
| avatar_XX_16（装孔径内） | 16×16 | 512×512 | 16 ~ 24 | **1 ~ 1.5** | 同上 |

> **与 §4.1「双网格」的关系**：上表 1.5m 下的等效颗粒 1~1.5 是**AR 层（世界锚定）**口径；同一张贴图若被当作**屏幕层元素**使用（如结算卡上把头像当 HUD 贴），按屏幕层口径取**固定颗粒**。**同一张图在两层颗粒不同，是口径差异，不是矛盾。**

**4. 与命中判定的关系（只声明视觉事实，不定义逻辑）**
- 命中以 `worldToViewportPoint` 的 `(0.5,0.5)` **视口容差 0.17** 为基准（**逻辑交主程序**）。本层只声明视觉侧事实：准星固定在屏幕正中，Boss 由玩法驱动"走进"该容差窗。

### 4.6 已知颗粒不一致（技术债）—— **本轮不修**，登记备查

> **口径**：**颗粒 = 显示屏幕 px ÷ 逻辑 px**。**项目基准颗粒 = 2**（由 `boss_body_idle`：逻辑 128 → 显示 256 定）。
> **根因**：导出硬上限「长边 ≤512」迫使每张资产的整数倍 `N = ⌊512 ÷ 逻辑长边⌋` **各不相同**，而显示档又只能取 `1/2^n` → **颗粒 = N ÷ 2^n 各不相同**。**这不是画错，是规格的数学后果。**

**A. 实测（真机 / 文件层面观察到）**

| # | 现象 | 证据 | 影响 / 处置 |
|---|---|---|---|
| A1 | 16 网格头像装进 16 逻辑孔径后，**描边 1px 膨胀会吃掉暗行** | sprite-art 手绘实测 | 已用规范消解：面部左右各留 1px 主色（§3.2） |
| A2 | **暗部面积过大会淹没主色**（16×16 下辨识度崩） | 同上 | 已用规范消解：暗部 ≤ 主色 1/2 + 1 行分隔（§3.2） |
| A3 | **合并 md5 不可复现**：`md5sum *.png \| md5sum` 路径敏感，同一批文件实测得 **3 个不同值** | art / sprite 双向独立复现 | 验收口径已改 **per-file `MANIFEST.md5`**（§5.3 第 8 条） |

**B. 推断（由 §4 规格表算出，**未经真机逐项验证**）**

| # | 资产 | 逻辑 | 显示 | **颗粒** | 与基准 2 偏差 | post-MVP 修？ |
|---|---|---|---|---|---|---|
| B1 | `avatar_XX_64`（选择器） | 64 | 64×64 | **1** | 偏细 2× | 否（**有意**：选择器要细节） |
| B2 | `fx_num_atlas`（普通档） | 160 | 240×24 | **1.5** ❌**非整数** | 偏细 | **是**（post-MVP 归一） |
| B3 | `ui_word_win` / `ui_word_lose` | 96 | 240×80 | **2.5** ❌**非整数** | 偏粗 | **是**（post-MVP 归一） |
| B4 | `boss_eye_*`、`boss_shield_core`、`boss_head_frame_a`、`avatar_XX_16`、`fx_lock_ring`、`muzzle_flash`、`hp_frame`、`hp_fill`、`hp_shield_fill`、`ui_panel`、`btn_backplate`、`ui_grade_*`、`card_bg` | 见各表 | — | **4** | 偏粗 2× | 否（UI 小控件粗颗粒本就是街机风） |
| B5 | `fx_num_atlas`（暴击档 1/1） | 160 | 480×48 | **3** | 偏粗 | 否 |

> **非整数颗粒是硬缺陷**（B2 / B3）：1.5× 与 2.5× 会让色块**在屏幕上宽窄不一**，破坏「像素块严格均匀」。列为本轮**已知缺陷**，接受在 MVP 内存在。

**C. 归一方案（post-MVP，**本轮不执行**）**
把非 2 幂逻辑尺寸（**24 / 96 / 160**）在**不损剪影**前提下改为 2 幂（32 / 128 / 128 或 160），即可让全部资产锁定 **颗粒 = 2**，达成「同一双手」的最终一致性。

> **本轮为何不修**：① 改动会波及已入引擎的导出尺寸与 GUID 引用；② 96 / 160 是"标题字 / 数字图集"的**版式最优解**，改 2 幂会牺牲排版；③ B6（AR 层）真机未验证，是主因。**风险在此登记，不在本轮消化。**

### 5.3 导出与导入规范（逐条硬约束）
1. **导出**：从逻辑网格按 ×N 整数倍最近邻放大到上表「导出(px)」尺寸，**透明背景 PNG-32**。
2. **色值**：导出前**调色板量化到 DB16**，导出 PNG 的**唯一色数 ≤ 16 且 ⊆ DB16**。
3. **Alpha**：只允许 0 或 255，**禁中间 alpha / 羽化 / 抗锯齿**。
4. **导入（每张逐项设）**：`filterMin=Nearest`、`filterMag=Nearest`、`filterMipmap=None`、`enableMipmap=false`、`Max Resolution=Size512`、`wrapModeS/T=Clamp`。
5. **显示**：只用 1/1、1/2、1/4、1/8、1/16（2 的整数次幂分之一）或整数倍放大（如结算卡 2×）；**禁任意百分比缩放**。
6. **旋转**：只允许 0°/90°/180°/270°；倾斜角用预烤帧，不做连续旋转。
7. **包体**：单张 ≤ 512×512；总包体 ≤ 2MB（核算见 6）。
8. **校验件（v2.1 新增，硬约束）**：**每个交付目录必须附 1 份 `MANIFEST.md5`** —— 格式 = `md5sum` 原生（`<md5><两空格><filename>`）、**ASCII**、**LF 换行**（禁 CRLF，否则跨平台 `md5sum -c` 报格式错）；只收该目录的**运行时图像资产**（**不收** `.json` / 对照图 / 清单自身）。
   - **判定「逐字节未变 / 内容一致」一律以 `cd <dir> && md5sum -c MANIFEST.md5` 全部 OK 为准。**
   - **❌ 不接受「合并 md5」**（如 `md5sum *.png | md5sum`）作为证据 —— 它哈希的是 `md5sum` 输出的**文本**、**内含路径**，路径写法 / 平台一变值就变（本项目实测同一批文件得 **3 个不同值**），**不可复现 = 不可审计 = 视同未提供**。
   - 清单**由生成脚本自动重写**，防手写漂移（范例：`tools/make_avatars.py` 的 `write_md5_manifest()`）。
   - **`MANIFEST.md5` 不计入贴图张数与体积**（非图像、引擎不导入）；**打包 glob 只收 `*.png`**，不得把它扫进包体。
9. **包体实测口径（与 `tech-spec §3.2` 一致）**：总包体**唯一判据 = 实测 `Σ artifactFileSize` ≤ 2048 KB**（含全部序列帧）；**估算值（含 §6 的 1.47 MB）只作预警，不作达标依据**。

### 5.4 与上下游接口（只定义「长什么样」，不定义「发生什么」）
- **交互逻辑 / 命中判定 / 状态机** → 主程序；本文件只给视觉状态清单。
- **时间轴 / 序列帧节奏 / 摆动曲线** → 动画总监；本文件只给关键姿态与帧预算（≤24）。
- **粒子数量 / 发射器 / 辉光 / 震屏幅度** → 特效总监；本文件只给粒子贴图与 DB16 用色，粒子总数红线 ≤50 由特效总监落实。
- **音频** → 音效总监；本文件不涉及。

## 七、美术侧 AI 生成可行性（本机像塑 MCP `generate_image` / `generate_assets_batch`）

### 7.1 结论（先给答案）
**不推荐用 AI 直接生成成品像素贴图交付。** 推荐 **「AI 只用于概念/剪影参考 + 人工在像素网格重绘」**，或 **「AI 生成 → 降采样 → DB16 量化 → 人工修边」的半自动流水线（仅适合边框/纹理类，不适合角色剪影）**。

### 7.2 为什么不能直接生成
| 硬要求 | 扩散模型产出 | 冲突 |
|---|---|---|
| 严格 16 色、色值 ⊆ DB16 | 生成图通常数百至数万色、带渐变与抗锯齿过渡色 | ❌ 直接违反「色值全部命中 DB16」 |
| 像素对齐（严格整数逻辑网格） | 输出非整数网格、半像素、抖动噪点 | ❌ 违反「无半像素」 |
| 1px 干净描边、封闭剪影 | 描边粗细不均、断线、糊边 | ❌ 剪影辨识度不达标 |
| alpha 仅 0/255 | 边缘必有半透明羽化 | ❌ 违反「边缘无羽化」 |
| 512×512 定量、DB16 无损 PNG 小体积 | 高噪点/多色 → PNG 压缩差、体积膨胀 | ❌ 包体风险 |

### 7.3 推荐做法（三档，按可靠性排序）
1. **纯手绘（首选，最稳）**：整包 37 张全手绘。理由：全部是**小图 + 平涂 + 受限色板**，一人可完成；风格一致性 100% 可控，验收零风险。
2. **AI 生成「概念/剪影参考」→ 人工重绘**：用 `generate_image` 出「圆滚石魔/街机相框」的**造型灵感图**（非交付），人工据此在 128 网格上重画。**参考图不进包体、不登记为资产**，只登记为「灵感来源」。
3. **半自动流水线（仅限边框/底纹类）**：
   `AI 生成 → 最近邻降采样到逻辑尺寸 → 最近邻量化到 DB16 → 人工逐像素修边（补 1px 描边、去半像素）`。
   **适用范围**：`ui_panel` 边框、`card_bg` 底纹、`hp_frame` 铆钉这类**规整几何**；**不适用**于 Boss 本体与眼睛（剪影/神态对像素精度极敏感，AI 修不回来）。

### 7.4 AI 路径风险登记（必须写进 SOURCES.md）
| 风险 | 说明 | 处置 |
|---|---|---|
| 版权/来源 | AI 图可能与训练数据相似，触发素材版权审核 | 只作参考不作交付；交付件必须人工重绘并可在工程中逐像素复现 |
| 色板溢出 | 生成含非 DB16 色 | 强制调色板量化 + 验收脚本断言 |
| 像素不齐 | 半像素/非整数网格 | 降采样到逻辑网格后再量化；人工修边 |
| 边缘羽化 | 半透明 alpha | 二值化 alpha（0/255）+ 修边 |
| 体积膨胀 | 杂色导致 PNG 变大 | 量化后复测单张体积 ≤ 45 KB |

> **判据**：AI 产出**必须能通过「八、验收标准」全部条目**才算合格交付；不能通过的一律人工重画，不给 AI 开后门。

## 八、美术验收标准（像素级可判定，逐条 pass/fail）

| # | 验收项 | 判定方法（可核对） | 通过标准 |
|---|---|---|---|
| 1 | 色板合规 | 脚本读每张 PNG 全部像素，取唯一 RGB 集合 S | `|S| ≤ 16` 且 `S ⊆ DB16 16 色列表` |
| 2 | 无羽化 | 检查 alpha 通道取值集合 | alpha 仅含 0 与 255，无中间值 |
| 3 | 无抗锯齿 / 无半像素 | 逐行/逐列扫描：任意 1px 线两侧无过渡色；缩放倍率整除 | 边界为硬跳变；导出 = 逻辑 ×N（整数）；显示 = 导出 × 1/2^n |
| 4 | 导入参数正确 | 逐张贴图查 `filterMin/Mag/Mipmap/enableMipmap/MaxResolution/wrap` | Nearest / Nearest / None / false / Size512 / Clamp |

## 十、与动画总监的帧预算裁定（v1.1 增量，新增 2 张贴图）

> 背景：动画总监采纳「身体/眼睛分离」结构后，本体序列帧由 66 瘦身到 51；就 4 个待定项请我拍板。以下为裁定。

**裁定 A1 —— 受击闪白：出 `white_flash_mask` 贴图（静态白剪影），不依赖引擎 tint**
- 规格：逻辑 **128×128**，导出 ×4 = **512×512**，显示 1/2 = **256×256**，与 `boss_body_idle` **同锚点、同锚定尺寸**（错位即露边，打击感崩）。
- 造型：**idle 剪影外扩 1 逻辑像素的闭合纯白剪影**（外扩 1px 让同一张同时覆盖 idle 与 enrage 微胀两种体型；薄白边本身即合格的冲击光晕）。
- **颜色 = `#deeed6`（DB16 近白），严禁 `#ffffff`**——否则破 16 色板，验收第 1 项直接不过。
- 用法：白闪 1–2 帧（与 hitstop 同帧）；**白闪结束后立刻切 `boss_eye_hurt`** 显示「眯眼龇牙」（设计案 4.1）。→ **`boss_eye_hurt` 保留**（白闪期眼睛被盖，闪后显示表情，二者不是二选一）。
- 理由：引擎 `Screen Image` 的 color 多为**乘算 tint（只能压暗、不能提亮到全白）**，赌 tint 能力有风险；一张 mask ≈3 KB，**直接出图、删除该依赖**，不需再找主程确认 tint。

**裁定 A2 —— 眨眼：出 `boss_eye_closed`（16×16）**
- 规格：逻辑 16×16，导出 ×32 = 512，显示 1/8 = 64×64，与 `boss_eye_*` 同网格、同挂点 (64,56)。
- 造型：`#140c1c` 单横线（眼缝）+ 上下眼睑 `#346524` 各 1 逻辑像素。
- 节奏：每呼吸循环眨眼 1 次，闭眼帧停 2 帧；**不做半闭**（省一张图）。
- 结论：IDLE 本体纯呼吸 4 帧，眨眼走眼睛叠层换图。

**裁定 A3 —— ENRAGE_LOOP：静态停帧（不出 4 帧呼吸变体）**
- `boss_body_enrage` 单帧；动感由 ① 整数像素上下 bob（±2px，周期 ~0.5s）② `boss_eye_rage` 闪烁 ③ 体缘红晕脉动 承担。
- 理由：阶段 2 满屏弹幕+震屏，本体形变辨识度低、投入产出比差；省 4 张 512×512（≈140 KB）。**P2 备选**：若测试嫌暴怒太死，补 **2 帧**（不是 4 帧）呼吸变体。

**裁定 A4 —— 挂点确认**：独眼挂点 (64,56)/直径 28/显示 64×64；旗杆挂点 x[52,76] y[2,26]；`FLAG_DROP` 避开本体描边、牌与头各自独立描边。**已确认，与动画总监绑定方案一致。**
