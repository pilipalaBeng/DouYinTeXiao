# ar-boss-raid · AR 像素 Boss 战互动特效

> **一句话**：手机镜头拍实景 → **真实空间里锚定**一只像素大 Boss（头顶挂着**你选的像素头像**：预设 6 选 1；摄像头取像为**待验增强**）→ **转动手机把它转进屏幕正中的准星、按住开火** → 把它打服认输，就赢了。
> **出口**：抖音特效开放平台（像塑 / Effect House）**提审准备包**。
> **当前状态（v2）**：口径已全面切换为 **AR 空间锚定**。**已验** = `AR Plane` 组件可搭 + 判定式归一化（`vp.y≈0.522`）+ PC 预览行为；**未验** = 核心玩法手感（"转手机把 Boss 转进准星"依赖真机 SLAM，见 `node-plan §4` #3/#8）。完整工程（多阶段/音频/UI）尚未开始。

## 一、怎么玩（30 秒版）

| 步 | 做什么 | 发生什么 |
|---|---|---|
| 1 | 打开特效，镜头对准房间 | 摄像头透传（平台底层）；Boss **锚定在真实物理空间**（3D 世界坐标），随镜头转动在屏幕上相对滑动 |
| 2 | **转动手机**把 Boss 转进屏幕正中准星 → **按住屏幕开火** | 屏幕下缘常驻一把**古代像素战弩**（HUD，不遮挡准星）；4 发/秒；命中（视口容差 **0.17**）出闪白 + 像素星 + 伤害数字 + 轻震 + 顿帧 + 音效（同帧） |
| 3 | 打空血条三阶段 → 最后 Boss 举手认输 | 彩带 + 星星爆炸 + 结算文案；**结算后准星自动隐藏**（防污染画面），重开恢复 |

**Boss「圆滚魔像」三阶段**：HP≤66% 暴怒变奏 → HP≤33% 举盾（打核心点 3 次破盾 → 2s 全额伤害窗 → 最多回盾 2 轮）→ HP≈15% 装死（0.8s，别停火）→ HP=0 认输。

> **2026-10-14 细节修改批次（已落地 + 运行期验证）**：① Boss 造型由地面独眼石魔换为**空中飞行怪（蝙蝠状）**并具备**空间内浮沉/漂移飞行**；② 新增**玩家武器 = AK 造型像素枪**（屏幕层 HUD，压在准星之下）；③ **准星在结算（胜利/失败）后隐藏**、重开恢复；④ 结算文案 **「失败！」**（原「败北…」废弃）。**吐火球 + 下蹲躲避已砍**（实测脚本层无任何设备姿态/高度传感器）。详见 `game-design-doc §十四`。**注（2026-10-15）：② 的武器题材已由「AK 造型像素枪」改为「古代像素战弩」；③④ 之后的头像/出战牌功能已整体废除（见九之二 #11）。**

**为什么是"转手机瞄准"**：v2 由官方对象 `AR Plane`（configId `PlaneAR`）一键搭出 AR 场景，**自动创建 `AR Camera` + `DeviceTracker`**（`trackingMode=World`，6DoF 全 3D 世界跟踪）；Boss 是 **3D 版 `Image` 对象（`ImageEntity`）**，锚定在真实空间。**"转动手机把 Boss 转进准星"就是你要的"移动手机瞄准"体验本身** —— 不再用"手指拖准星"，准星固定屏幕正中、不可拖拽。

## 四、合规与平台边界（不可放宽）

- **头像双轨（合规命门）**：**轨 A（默认）**＝内置**预设 6 选 1**，零真人照片、零上传；**轨 B（待验增强）**＝摄像头取像，用户**主动对准当前在场者**拍摄，**不存储 / 不上传 / 不导出**，仅存活于本局运行时纹理。两轨均**只做静帧贴片**，不做表情驱动 / 不换脸 / 不做人脸识别 / **不导入任何外部照片**；**未选 / 跳过 / 取像失败均回落轨 A、不阻断进局**。
- **去暴力化**：全程 **无血、无伤口、无惨叫、无身体碎片**；终结语义是"**认输 / 被放倒**"，不是"杀死"。命中反馈**只许白/黄**像素星，**禁用红 `#d04648`**（会被读成血）。
- **零人声**：全包不含任何人声采样 / TTS。
- **不做**：复杂 3D 骨骼、实时物理、服务器下发、任何社交/通讯录 API（平台无此能力）。

## 五、★ 头号红线风险

**单张 512×512 序列帧体积口径打架，可能撑破 2MB 包体。**

| 口径 | 单帧 | 53 帧 | 总包体 |
|---|---|---|---|
| 乐观（动画原估） | 5–12 KB | 0.53–0.64 MB | **≈1.45 MB**（余量 1.4×） |
| **悲观（美术实测锚点）** | **28–45 KB** | **1.48–2.38 MB** | **≈2.10–3.00 MB → 破线** |

**唯一一锤**：首批导出 1 张真实 Boss 帧，读 `artifactFileSize`。降级阶梯已备：① 先测后砍 → ② 小元素降导出尺寸（32→256）→ ③ 帧数压缩 → ④ 砍 BGM（256KB，第一顺位）→ ⑤ 最后才动宪法参数。**门禁必须逐张校验、且含全部 53 个序列帧文件**（只测静态贴图会得出错误的"包体很宽松"安全感）。

## 八、★ PC 预览 vs 真机（AR 验收先读；否则会把正常行为误判成 bug）

**实测结论（是行为特性，不是 bug）**：**PC 预览下没有 SLAM**，AR 相机需要约 **4 秒**缓慢收敛，Boss 才会从屏幕外滑进准星。

- **PC 预览**：必须**长按开火 ≥7 秒**才能看到命中；**2 秒内开枪必然全 miss** —— 这是 PC 预览无 SLAM 的正常表现，**不是功能坏了**。
- **真机**：有 SLAM，**转动手机实时响应**，Boss 随镜头即时滑动，无需任何等待。

**因此 PC 预览的验收口径**：
- **可以**用 PC 预览验收"链路连通"（Boss 能滑进准星 → 命中能掉血 → 反馈同帧），但**必须长按开火 ≥7 秒**；**不得**拿"2 秒内看到命中"当 PC 预览的通过条件。
- **手感 / 跟手性 / 响应延迟只能真机验收**，PC 预览的延迟不具参考性。
