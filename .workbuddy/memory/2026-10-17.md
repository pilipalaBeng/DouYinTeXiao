## 血条改造：纯色 Image + Delay Health Bar

作者反馈「boss血条这的资源还是有问题」，要求「别用资源做了，直接用纯色的 image 做，一个当背景板一个当血条，使用 Delay Health Bar 方法」。

### 🔑 关键发现：纯色 Image 根本不需要任何素材
`Image` 组件的 `texture` **默认值就是内置的 `Default_Texture`**
（guid `00000000-0000-0000-0000-0000000000c0`，`builtin_name: Default_Texture`）。
所以「纯色块」的做法 = **内置白图 + `color` 染色**，零素材。
（白图 × color = 纯色；若保留原素材再染色，纹理细节仍在，不是纯色。）

### 场景改动（三层，自下而上）
| 对象 | 组件 | 改造 |
|---|---|---|
| 战斗HUD底板 s28 | ScreenTransform c49 / Image c50 | texture→内置白图、color→**#442434 深紫**、stretchMode→**Stretch** |
| **Boss血条延迟 s57（新建）** | ScreenTransform c97 / Image c98 | 内置白图、color→**#dad45e 黄**、Stretch；位置/尺寸复制自血条填充 |
| Boss血条填充 s29 | ScreenTransform c51 / Image c52 | texture→内置白图、color→**#d04648 红**；保持 drawMode=Filled |

- 新建对象用 `add_builtin_object{object_type:"Screen Image", parent:"s24"}`，
  再用 `move_scene_object{above_scene_object:"s28"}` 修正层级（新建对象会插到父的最前面 = 最下层）。
- 三层颜色都取自 AGENTS.md 的 DB16 色板 ✓

### ⚠️ 踩到的坑（都写进这里，别再犯）
1. **`stretchMode` 必须显式改 `Stretch`**：内置白图是**正方形**，而 Fit 会保持比例 ⇒ 640×96 的框只渲染出
   中间 ~96×96 的小方块，长条铺不满。血条填充本来就是 Stretch 才没中招。
2. **短 id 不能塞进 `$ref`**：`{"guid":{"$ref":"s28","component_type":"Image"}}` 报
   `$ref "s28" has no "Image" component`。改用**组件 GUID 直接传**（`"guid":"c50"`）⇒ 成功。
3. **材质共享**：底板/血条/延迟条共用材质 `r4`。即时条用材质属性 `_filledRange` 驱动，
   所以**延迟条不能用同一套**（两个 `_filledRange` 会互相打架）⇒ 延迟条改用 **sizeDelta 缩放**。

### 代码实现（Assets/GameManager.ts）
- 常量：`HP_DELAY_WAIT_MS = 400`（受伤后延迟条先停顿）/ `HP_DELAY_SPEED = 0.7`（每秒追平比例）
- 字段：`hpDelay` 对象、`hpDelayRatio`、`hpDelayWait`、`hpDelayFull`、`hpDelayLeft`
- `create()`：取对象 + 记下满宽与**左边界**（缩放时左边界固定，否则会从中间缩、方向感全错）
- `hit()`：`hpDelayWait = HP_DELAY_WAIT_MS` 触发延迟
- `updateHpDelay(delta)`：**即时条**由 `_filledRange` 立刻跟随；**延迟条**先停 400ms 再按 0.7/秒追平，
  同步 setDisplaySize + setPosition 保持左边界不动
- `resetGame()` 重置 `hpDelayRatio/hpDelayWait`；`finish()` 隐藏延迟条

## 结算数据真实性审计 + 评级改为真实计算（08:45）

作者：「这里结算的时候显示 耗时命中率和评分都是真实的吗？如果是假的话，那就给他一个真数据」

### 审计结论（读代码确认，不靠印象）
结算文本原本只有一行：
```ts
this.resultStats.setText(`同步率 ${hits*100/shots}%\n连击 ${maxCombo} 评级 ${win ? 'B' : 'C'}`);
```
| 项 | 来源 | 判定 |
|---|---|---|
| 同步率（=命中率） | `hits * 100 / shots`，shots 在 `fire()` +1、hits 在 `hit()` +1 | **真** |
| 连击 | `maxCombo`，命中 +1 / 未命中归零（`fire()` 里 `!aimed` 时 combo=0） | **真** |
| 评级 | `win ? 'B' : 'C'` | **假（硬编码）** ← 打得再好也是 B |
| 耗时 | 无 | **压根没这项** |

作者说的「耗时」原本就是缺的 ⇒ 补上。

### 改动（Assets/GameManager.ts）
1. **结算文本改为三项真数据**：
   `耗时 {Math.round(elapsed)}s  同步率 {acc}%\n连击 {maxCombo}  评级 {gradeResult(win)}`
2. **新增 `gradeResult(win)`**，替换硬编码评级。公式透明可复现：
   `分数 = 命中率归一×50 + 速度×30 + 连击×20`，映射 S/A/B/C；未击杀（含超时）一律 C。
3. **评分参数全部提为顶部常量**（单一来源，要调只动这里）：
   `GRADE_WEIGHT_ACC/SPEED/COMBO = 50/30/20`、`GRADE_ACC_FULL = 0.8`、
   `GRADE_SPEED_CEIL = 30`（秒，用满即 0 分）、`GRADE_COMBO_FULL = 20`、
   `GRADE_S/A/B = 85/70/50`

### 为什么要有 `GRADE_ACC_FULL = 0.8`（命中率满分线）
打**护盾核心**的射击走 `coreHits += 1`，**计入 shots 但不计入 hits**（见 `resolveArrowHit`）
⇒ 命中率天然到不了 100%（实测推演一局全中约 83%）。
不设满分线的话 `acc×50` 最高只有 ~41 分，**S 不可达**。以 80% 为满分基准后 S 才够得着。

### 验证
1. **独立验算**（Python 复现公式）——分布单调、S 只在顶尖表现出现：
   | 场景 | 命中率 | 耗时 | 连击 | 得分 | 评级 |
   |---|---|---|---|---|---|
   | 顶尖 | 83% | 11s | 28 | 89.0 | **S** |
   | 优秀 | 76% | 14s | 24 | 83.7 | A |
   | 良好 | 68% | 18s | 16 | 70.2 | A |
   | 一般 | 57% | 22s | 9 | 52.7 | B |
   | 勉强打完 | 44% | 27s | 4 | 34.8 | C |
   | 失败(超时)/一枪没开 | — | — | — | 0 | C |
2. **PC 预览实测**：临时注入顶尖成绩（36 发 / 30 中 / 11s / 28 连击）+ 走胜利流程
   ⇒ 结算显示 **「耗时 11s 同步率 83% / 连击 28 评级 S」**，与 Python 验算完全一致 ✔
   文本两行未溢出结算卡 ✔
3. 探针全部撤除，编译 exit_code=0，已 save_project。
   截图：`.workbuddy/shots/result-real-stats.jpg`

### 备注
- 标签仍是「同步率」（世界观用语），语义上就是命中率；作者若想改字面为「命中率」一行可改。
- 评级公式的权重/分数线都集中在 GameManager 顶部 `GRADE_*`，作者想调手感只动那几个常量。

## 街机风「连击 HIT」显示（09:30）

## HIT 显隐过渡动画（09:35）

作者追问：「hit 相关的 ui 只有在击中的时候才会显示出来，如果当前没有被击中就是隐藏的，击中后只要在一定时间内就会一直显示，
一段时间内没有再次击中就会消失···这个你可以看看其他游戏的 hit 显示怎么做的，还有动画效果什么的都可以借鉴」

### 问题
原实现是**硬切**：`combo < 2` 直接 `setVisible(false)`，命中直接 `setVisible(true)` —— 数字"啪"一下出现/消失，没有过渡。

### 改法：显隐状态机（借鉴鬼泣/无双那类）
`hitPhase`：`0 隐藏 → 1 入场 → 2 保持 → 3 离场 → 0`

| 阶段 | 时长 | 表现 |
|---|---|---|
| **入场** | `HIT_IN_MS = 180` | scale **0.6 → 1.15（冲过头）→ 1.0（回弹）**，同时前 40% 时长内 alpha 0→1（弹出感） |
| **保持** | —— | 轻微**呼吸** `1 + 0.02 × sin(elapsed × 6)`，让静止数字不显死板 |
| **离场** | `HIT_OUT_MS = 200` | scale 1 → **0.85**、alpha 1 → **0**（同时淡出缩小），结束后隐藏 |

- **命中脉冲**（punch）与状态机缩放**相乘叠加**：`最终 scale = base × punch`；抖动只加在位置上
- 淡出途中**再次命中** → 直接切回入场，数字不会丢
- 透明度量化到 0.05 步长做脏检查（避免每帧重排版）

### 🐛 踩到的 bug（已修）
第一版淡出时**闪了一下「0 HIT」**：断连瞬间 `combo` 归零，而第 4 步还在按 combo 刷文本
⇒ 屏幕先闪 "0 HIT" 再淡出。
**修法**：`if (this.hitPhase !== 3)` 才更新文本/颜色 —— **离场期间冻结内容**，保持最后一击的数字淡出。

### 关键技术点
**`GameObject.setAlpha` 对 Text 无效** —— 它内部只找 `Image` 组件，而 Text 对象没有 Image ⇒ 静默不生效。
Text 的透明度要改 Text2D 的 **`letterAlpha`**（`getEngineComponent('Text2D')`）。

### 验证（PC 预览）
PC 帧率只有 1.5~5 FPS，**真实 180ms 的动画会被一帧跨过**，看不到曲线。
⇒ 临时把 `HIT_IN_MS/HIT_OUT_MS` **放大 10 倍**（1800/2000）+ 探针涨到 6 连停手，才看清：
`4 HIT`（入场中，偏白）→ `6 HIT`（保持，黄）→ `6 HIT`（**淡出中，明显变淡但仍是 6**）→ 完全消失 ✔
截图：`.workbuddy/shots/hit-appear.jpg`（入场）、`hit-fadeout.jpg`（淡出中）
验证完已把时长改回 180/200、探针全部删除。

### 备注
真实手感只有**真机**能评估（PC 帧率不足以还原 180ms 动画）。若真机上觉得入场太快/太慢，
调 `HIT_IN_MS`（现 180）/ `HIT_OUT_MS`（现 200）/ `HIT_IN_OVERSHOOT`（现 1.15）。

## 护盾 / 核心按 Boss 实际距离缩放（15:47）

作者：「修改像素护盾显示的时候要以怪物当前的 scale 和距离进行设置，要不然怪离得太远的话护盾会很大，离玩家太近的话，护盾又很小」

### 问题根因
护盾（`护盾覆盖` 280×178）与核心（`护盾核心` 52×52）都是 **2D 固定尺寸**，
而 Boss 是 **3D 空间物体**：`syncFollowers()` 里只同步了**位置**（`setPosition(bossScreenX, bossScreenY)`），
**没同步尺寸** ⇒ 玩家走动改变与 Boss 的实际距离时，屏幕上 Boss 近大远小、护盾尺寸纹丝不动 ⇒ 错位。

### 修法（Assets/GameManager.ts）
- 新增字段：`shieldBaseW/H`、`coreBaseW/H`（开局从场景读一次基准尺寸）、`shieldScale`（脏检查缓存）
- 新增 `bossDistanceScale()`：`clamp(SPAWN_DIST / dist, 0.4, 2.5)`
  - `dist` = 相机世界位置 → `bossPos` 的实际距离
  - **`SPAWN_DIST`（18m）为 1.0 基准** ⇒ 基准距离下护盾保持原设计尺寸
  - 透视关系正确：屏幕尺寸 ∝ 1/距离，所以远（dist>18 ⇒ k<1）护盾就变小、近（k>1）就变大
  - 钳在 0.4~2.5：防相机位置异常时把护盾缩成针尖或撑爆屏幕
- `syncFollowers()` 里应用：`setDisplaySize(base × k)`，带 1% 脏检查（避免每帧新建 Vector3f 写 transform）
- `setDisplaySize` 内部以 **sizeDelta** 为基准算 scale ⇒ **重复调用不会累积误差** ✔

### 验证（PC 预览）
PC 上 Boss 距离恒定、且常贴右边缘（护盾会被裁掉），没法自然验证
⇒ 临时探针：`bossDistanceScale()` 用 `elapsed` 循环返回 `[0.6, 1.0, 1.8]` + 强制显示护盾并挪到屏幕中心。
三帧截图确认：护盾（蓝色弧形）与核心（橙色菱形）**明显随之变大/变小**，且两者**同步缩放** ✔
验证完探针全部删除，编译 exit_code=0，已 save_project。
截图：`.workbuddy/shots/shield-scale-small.jpg` / `shield-scale-large.jpg`

### 待真机确认
- 真机上玩家走动时，护盾是否紧贴 Boss 轮廓（现在按"透视比例"跟，理论上精确）
- 若觉得护盾跟随缩放太"跳"，可对 k 做平滑（lerp），目前是直接取用

## 分析：Boss 飞行「有时看得见、有时越飞越近然后消失」（16:10）

作者：「分情况的 有时候好，有时候坏的」

### 结论：不是随机 bug，是三个已知设计叠加的必然结果
1. **yaw 是「无边界随机游走」** —— `orbitStep()` 里 `orbitYaw += orbitYawVel * dt`，速度方向每帧随机抖动、
   大小被归一化成恒定角速度 `omega = BOSS_SPEED/SPAWN_DIST = 5/30 = 9.55°/s`。
   一局 30 秒（扣掉 `BORN_HOLD_MS=2500` 静止）实际绕飞 ≈ 27.5 秒 ⇒ **累计可转到 260°+**。
   方向每 ~5 秒随机换一次 ⇒ **有时在前方晃（好），有时一路转到侧后方/背后（坏）** ← 「时好时坏」的直接来源
2. **转到背后就被硬关掉** —— `projectBoss()` 里 `bossOnScreen = sp.z > 0.2`，
   `syncFollowers()` 里 `bossSpatial.enabled = bossOnScreen && phase !== 'result'`
   ⇒ 相机空间深度一旦 ≤0.2（到侧面/背后），对象**直接 disable**，视觉上"啪"一下消失（不是渐变淡出）
3. **球心 / 参考基整局钉死**（`ORBIT_FOLLOW_CAMERA=false`、`ORBIT_FOLLOW_HEADING=false`）
   ⇒ 真机上玩家**转身/走动**后，Boss 仍绕「开局那一刻的球心 + 开局朝向」飞：
   转身 → Boss 跑到背后；走远 → 距离 >30m 缩小出框。位置钉死是作者要的"空间感"，但副作用就是容易丢失目标

### ⚠️ 顺带发现：一处注释与代码不一致（隐患）
`SPAWN_WAIT_MS` 的注释写着「**现在球心每帧跟随相机**，即便开局锚点算错也会立刻被纠正（不再需要长等待兜底）」，
但 `ORBIT_FOLLOW_CAMERA = false` ⇒ **球心并不跟随**。
⇒ 当初把等待从 2500→1200ms 的依据**已失效**：若开局 1.2 秒内 SLAM 还没就位、相机仍在原点，
球心就被钉在 (0,0,0)，之后相机跑到真实位置也不会被纠正 ⇒ 整局距离/方位偏移。

### 建议（按侵入从小到大，待作者选）
- **A. yaw 限幅 ±75°**（最小改动、最直接）：`orbitYaw` 超出就反弹（和 pitch 一样处理）⇒ 永远转不到背后
- **B. yaw 加"回中力"**：`orbitYaw -= orbitYaw * k * dt`，越偏越往回拉 ⇒ 长时间稳定在前方附近
- **C. 球心"软跟随"**：玩家移动超过 N 米时把球心平移同样距离（静止时仍世界锚定）⇒ 走远也不会丢
- **D. 背后不硬关**：`enabled` 保持 true，或改成降低透明度 + 屏幕边缘方向箭头
- **E. 修注释 + 投放闸门加严**：相机未就位时宁可继续等（或按当前位姿先投放、就位后**重新锚定一次**球心）
