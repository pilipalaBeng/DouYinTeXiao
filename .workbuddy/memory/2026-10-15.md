### ★★ 用户质疑「弩能过审为什么 AK 不行」——考证结论（重要，别忘）
用户眼见成立了，且**修正了我首轮"必拒"的过重措辞**。定级应为「**高风险**」而非「必拒」——审核是机器+人工，有通过可能，不能替平台断言。**这条教训本身要记住：给平台审核下绝对断言 = 伪证据。**

但弩与 AK 确实不同类，**三条分界线**：
1. **法律定性**：公安部《关于涉弩违法犯罪行为的处理及性能鉴定问题的批复》公复字[2006]2号原文——「弩……其结构和性能**不符合《枪支管理法》对枪支的定义，不属于枪支范畴**」（按《公安部、国家工商局关于加强弩管理的通知》公治[1999]1646号管理，属管制器具，层级低得多）。而 AK-47 = **制式枪支**（公安部《仿真枪认定标准》术语：已完成定型试验、经军队或国家主管部门批准装备使用的枪支）。
2. **官方清单**：抖音特效规则「管制枪械/刀具」列举 = 坦克、装甲车、原子弹、**机枪**、弹簧刀、炸弹、防暴棍。**全是现代制式军事武器+爆炸物+管制刀具，清单里没有弩。**
3. **语境**：弩=冷兵器/古风武侠狩猎，有审美豁免传统；AK=现代军用写实形象。

→ **拿弩类推 AK 是跨了三条线的类比**，不成立。但也不能说 AK 必拒。准确口径：**高风险 + 改造成本≈0 + 被拒损失=整个工程**，所以不该赌。

### ★ 3D API 事实（重要，下次直接用）
- **3D 对象不能走 `Game2D.existing()`** —— 它要求 `ScreenTransform`，3D 对象会被拒（返回 null 并 warn）。
- 取 3D 对象：`this.sys.engineScene.findSceneObject(name)` → `APJS.SceneObject`
- 关键 API：
  - `obj.getComponent('Image') as APJS.Image`；`image.texture` / `image.size`（**世界单位**，默认 (2,2)）/ `image.opacity`
  - `obj.getComponent('Camera') as APJS.Camera`；`cam.worldToScreenPoint(v)` / **`cam.getLookAt()`**（相机朝向单位向量）/ `cam.screenToWorldPoint` / `cam.viewportToWorldPoint`
  - `obj.getTransform()` → `getWorldPosition()` / `setWorldPosition(v)` / `localScale` / `localEulerAngles`
  - ★ **`SceneObject.enabled` 才是可见性开关**（**没有 `visible` 属性**，写了会报 TS2339）
- `worldToScreenPoint` 返回**左下原点**像素坐标 + z=相机视轴距离；与 2D UI 左上原点不同，**必须翻 y**。

### ★★ 踩坑（必记）
- **PC 预览的 AR 相机位置完全不可靠**：探针实测 `cam=(-1.0, -50.4, 4.9)` —— **跑到地下 50 米且持续漂移**。任何"以相机为基准"的 3D 投放都会被投到屏幕外。

  → **结论：3D AR 空间位置在编辑器里无法验证，只能真机。**
- `viewportToWorldPoint` 与 `worldToScreenPoint` 实测**不互逆**（前者算出的世界点投影后跑到屏幕外）；**`getLookAt()` + 相机世界位置**才可靠。

### 几何硬伤（本轮核心发现）

## 续 · Boss 体积修正 + 头顶头像整体移除（像塑 MCP 实操）

### 1. Boss 观感过小的真因 = 缩放，不是距离
- `Boss空间体`（3D Image）场景里 size 默认 **10**；脚本 `create()` 写死 `new APJS.Vector2f(BOSS_CORE_SIZE, BOSS_CORE_SIZE)`，上一轮为"1 米距离别糊屏"把 `BOSS_CORE_SIZE` 从 1.15 砍到 **0.5** → 等于压到默认值的 **1/20**，这才是主因（投放距离从 3m 改到 1m 其实是**变近**）。
- 已改：`BOSS_CORE_SIZE` **0.5 → 1.0**；漂移球壳 `BOSS_MIN/MAX_DIST` 0.5/1.2 → **0.4/0.8**（不跟着改，投放变近后 Boss 会被旧下限立刻弹出去）；初始随机偏移 ±0.6/±0.4 → ±0.3/±0.2；场景端把 s68 的 `Image.size` 也设为 1。
- **3D Image 的 `size` 即世界尺寸**（与 Transform.localScale 相乘），调大小优先动 size。

### 2. 头顶头像/出战牌整体移除：场景与脚本必须**两头都删**
- 场景删：`Boss出战牌` s17、`Boss头像` s18、`结算头像` s40。
- 脚本删：字段 `badge/avatar/resultAvatar` + `create()` 赋值 + `syncFollowers()` + `finish()` + `showMinimalResult()` + `resetGame()` 共 **10 处**。
- **只删场景不删脚本 = 必崩且症状隐蔽**：`object()` 返回 undefined → `undefined.setVisible()` 报错 → `resetGame()` 中途抛错 → 结算文字隐藏不掉。症状是截图里出现**代码中根本不存在的文案**（如"评级 S"，代码只有 B/C），说明那是场景静态文本没被 hide。

### 3. ⚠️ 重大坑：像塑的脚本编译链（本轮新发现）
- 链路：`Assets/*.ts` →（watcher 同步）→ `Library/CompiledScripts/Src/*.ts` →（编译）→ `Library/CompiledScripts/Editor/*.js` ← **预览实际跑的是这份 JS**。
- **watcher 不一定立刻跟上**：本次就停在"我第二批编辑之前"，预览跑的是半新半旧代码（`Src` 副本 22875B vs 源 22687B，diff 恰好是我最后 5 处改动）。
- **改完 TS 的正确验证姿势**：等 2~4 秒后
  ① `ls -la Library/CompiledScripts/{Src,Editor}/GameManager.*` 时间戳须晚于 `Assets/GameManager.ts`；
  ② `grep -c "<刚删掉的符号>" Library/CompiledScripts/Editor/GameManager.js` 应为 0。
- **`run_otsc_check` 是 `--noEmit`**（`tsconfig.noemit.json`），**只查类型、不产 JS**：它 `exit_code=0` 只能证明"类型没问题"，**不能证明预览会跑对**。两件事必须分开验。
- 强制重新同步：对 TS 做一次**真实内容改动**（哪怕只修一行注释）即可触发 watcher。

### 6. ⚠️⚠️ 场景改动不落盘（本轮最重要发现）
- 像塑 MCP 的所有场景改动（删对象、新增对象、改 visible / size）**只活在编辑器会话内，不写 `project/Assets/main.scene`**。
- 证据：本轮删了 s17/s18/s40、建了 s68/s65–s67，但 `main.scene` 时间戳仍是 `17:08:46`（旧），文件内 `Boss出战牌/Boss头像/结算头像` 各 1 处、`Boss空间体` 与 `战弩拉弦模板` 均 **0 处**。
- 同时像塑**会**从磁盘删除关联导出资源（`Assets/DynamicAsset/7637045997423673382/好友选择/*` 已消失）→ 形成「资源已删、场景仍引用」的中间危险态。
- **结论：每次 MCP 场景改动后必须让作者在像塑里手动保存工程**，否则关掉编辑器全丢；不保存时旧 `main.scene` 还会引用已删资源。
- git 提交时 `main.scene` **不会出现在 diff 里**，别以为"没变化"就没事——要单独 `grep "<新建对象名>" main.scene` 验证是否落盘。
