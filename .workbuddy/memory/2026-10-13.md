### B. DSL 层新踩的坑（血泪，务必记住）
1. **`$ref` 只能引用"同批次内定义的 alias"**。跨批次写 `{"$ref":"s4"}` 会被当字面 GUID → 报 not found。
2. **短 id（`s1`/`c5`/`r3`）可以直接当 GUID 用**（`parent: "s1"` 成功），只是**不能**塞进 `$ref`。
3. **`add_builtin_object` 带 `parent` 是"先建对象、再执行 move"**：move 失败时对象会**留在根层变成孤儿**（我因此产生过一个孤儿"准星"）。批内失败会 skip 后续命令，但**已执行的不回滚**。
4. **`set_component` / `set_resource_properties` 的 enum 必须包成** `{"type":"Enum","data":"Nearest"}`；直接给字符串会报 `Cannot deserialize [object Object] to Enum`。
5. **`properties` 是对象（dict），不是数组**；写成数组会报 `Invalid property name undefined`。
6. **`set_component` 的 `guid` 用 `{"$ref":"sceneObj","component_type":"Image"}` 解析不了字面 GUID** → 直接传**组件 GUID**（`c5`）最稳。
7. **新子对象会插到父的"最前面"** → 渲染顺序（renderOrder 按 DFS 编号）= 后建的在**下层**。要修正用 `move_scene_object{guid,parent,above_scene_object}`。当前顺序已修为 Boss < 准星 < 血条 < 血条填充。
8. 组件 GUID 用 `get_scene(summary=false)` 一次全取，比逐个 `inspect` 省得多。

| DB16 硬边 · 128 逻辑 ×4 | 9,960 B | **3,731 B (3.64 KB)** | 193 KB ✅ |

### D. 像素化流水线（已工具化）

## G. ★★★ 编译/热更死锁根治（本轮最大阻断，已结案）

**症状**：`edit_script` 反复报 `Script compilation failed` / `{"compiled":false}`，但 `otsс -p <任一 tsconfig>` **exit 0 无报错**；产物 `Out/Scripts/*.js` **确实在更新**，可运行时日志始终是旧代码。

**取证路径（可复用的排查法）**：
1. 磁盘三层时间戳比对 → 发现 `Src/` `Out/` `Editor/Scripts/` 都在刷新，说明 TS 编译**没问题**。
2. 日志模式识别 → 每轮固定是 `ts project compiled success in ~500ms` **紧跟** `compile Scripts failed!`。失败在**第二阶段**（打包进运行时），不在 TS 编译。
3. **关键：读 `Instances/Instance1/UserScript/Log/compiler.log`**（这个文件不在工程目录内，容易被忽略）。里面有决定性一行：
   ```
   compiler error: task_1 forced __compile_all_and_wait__ done by Error:
   ENOENT: no such file or directory, open '...\Library\CompiledScripts\Out\Scripts\SensorProbe.js'
   ```

**根因**：早前探针脚本 `SensorProbe.ts` 被删除，但**编译器的「用户脚本清单」是内存态**——`compiler.log` 每轮都打 `script [SensorProbe] re-status: true`。它按表加载 `Out/Scripts/SensorProbe.js` → ENOENT → 第二阶段强制中断 → 运行时包永不重打包。

**⚠️ 排查中踩的坑**：注册表有**两份**，`Instance1/UserScript/UserScriptsHotMetadata.json`（工程级，真正生效的）和 `ProjectCreatedTmp/未命名/Library/CompiledScripts/Editor/UserScriptsHotMetadata.json`。我先改了后者，**改错文件**，白折腾一轮。两份都要看。

**解法（不需要重启编辑器）**：把 `SensorProbe` 还原成一个**可编译的空壳**（`Assets/Scripts/SensorProbe.ts` + `.ts.extra`，class 名与文件名一致，`isUserScript: true`）。ENOENT 消失 → `compile Scripts` 通过 → 热更恢复。空壳待编辑器重启后可用 `delete_script` 彻底清除（重启后内存清单会按盘上文件重建）。

**另一条实锤**：**直接改 `Assets/Scripts/*.ts` 文件内容能触发引擎重编译**（sed 改一个字符串即触发，产物刷新）；`touch` 只改 mtime 无效。所以脚本迭代可以绕开 `edit_script` 工具直接用文件写入，更快。
