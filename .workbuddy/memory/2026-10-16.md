## ar-boss-raid：Boss 拉近到 3 米 + 修「开火失效」

### 改动（提交 92778a1）
- `SPAWN_DIST` 6 → 3（作者要"拉近到原来的二分之一"，它同时是环绕飞行的恒定半径）；
  `BOSS_CORE_SIZE` 保持 3.0 **不动**（作者明令"只调我指定的值"，不联动缩放）
- **修「开火失效」**：`beginFire` 原准入是 `isRecording && phase !== 'result'`。
  `isRecording` 由录制事件驱动，`handleRecordEnd` 一旦收到 RecordEnd 就把它**永久置 false**
  且无恢复路径 → 之后 pointerdown 不再置 `fireHeld`，表现为「按屏幕完全不开火」；
  tick 开头的同款早退还会让整局停摆（HUD 冻结在 30s）。
  → `beginFire` 只保留 `phase !== 'result'`；`handleRecordEnd` 改为只收火 + 停音效，不再冻结整局。
- `fire()` 整体包 try-catch：中途抛错（如音效资源问题）不再静默毁掉开火链，打 `[fire-err]`
- 前 3 发打印 `[fire] aimed/boss 屏幕坐标/cross/on/phase`（真机验证用，确认后可删）
- `probeSpatial` 增加 `screen`(换算后左上原点) / `cross` / `aimed` 三个字段

### 学到的其他事实
- 场景「脚本」对象 s13 挂 `GameManager` 组件，其 `resGuid = r11`（脚本资源 GUID）。
  SKILL.md 里有 `edit_script`（"Replace and compile an existing script resource"），
  但它要传**完整源码**，手写 500+ 行风险太高，**本轮未采用**。
- `import_resource` 受 local path 传参，但本轮调用直接连接报错（可能是体积/超时）。
- 准星实际位置已核实：场景 `固定准星` anchoredPosition=(0,120) → 屏幕 (360,520)，
  与脚本常量 `CROSS_X/CROSS_Y` 一致，**不是**错位来源。
